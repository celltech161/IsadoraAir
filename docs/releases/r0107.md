# r0107 — iPortal foundation and evergreen voice tracking

Predecessor: **r0106** (`f65652a2830d2eb721defc05adfeb533acc6ef8c`).
Protected runtime: **generation 11 → 12** (runtime version stays 11).
Accepted engineering baseline: `ab5f5f91f432b30d6ca87e00a6d8160616860a60`
(2.22A + 2.22B), plus the release-preparation commits on
`release/r0107-iportal-foundation`.

## Release notes

### New

- **Native iPortal recorder/editor foundation** — a shared browser workstation
  (record, preview, trim/gain/fade edits) built on a reusable recorder contract
  (`production/recorder/`), with **browser drafts** that keep their own revision
  and belong to one user.
- **Immutable ProductionMedia storage** — every recording, upload and edit is a
  new immutable file with a database identity, provenance and validation state
  (`production` app; `docs/PRODUCTION_MEDIA.md`).
- **Evergreen VoiceTrack recording and editing through iPortal** — record,
  edit, save and bind a take for an evergreen `(Track, position)` VoiceTrack.
- **Non-destructive take replacement and history** — re-recording or editing
  binds a new take; earlier takes stay immutable; deleting a VoiceTrack removes
  the row, never shared media bytes.
- **Hardened media validation** — every uploaded or recorded file is checked
  by ffprobe, a full ffmpeg decode and the engine's own GStreamer decode, each
  run inside a kernel-confined, admission-bounded service.
- **Validation limits in Admin** — Production media → Validation limits:
  concurrent validations (default 2, allowed 1–4) and pending requests
  (default 4, allowed 0–8).

### Infrastructure

- New **`isadoraair-validation.service`**, the sole owner of every validator
  process: delegated cgroup v2 subtree (`Delegate=cpu memory pids`,
  `DelegateSubgroup=supervisor`), `KillMode=control-group`, `Restart=always`,
  private `0700` runtime directory with a `0600` socket and status file.
  Gunicorn is only its client (`Wants=`/`After=` it).
- New **protected-runtime generation 12**: the signed managed-unit policy gains
  exactly `isadoraair-validation.service` → `ENABLE_NOW`; nothing else changes.
- **ProductionMedia backup/restore**: the durable `media/` directory is in the
  nightly backup; `incoming/`, `work/` and `locks/` are not, and restore
  recreates them empty.
- **Validation host requirements** (checked before any change — see below).

### Compatibility

- Legacy VoiceTrack `filepath` playback is retained; a bound take wins and a
  bound take that is not playable degrades to the legacy file.
- Evergreen `(Track, position)` VoiceTrack semantics are unchanged.
- OGRemote is untouched and stays frozen.
- 2.22C spoken-content workflows and 2.6 occurrence VoiceTracking are **not**
  included.

### Operational note

Validation-limit changes made in Admin take effect only after a controlled
restart of `isadoraair-validation` (which cancels validations in progress;
those uploads stay unvalidated and can be validated again). Until then the
Admin page shows "Restart required".

## What the update does

Planned by Update Center from r0106 (no manual operations, no migration
approval, no apt/pip/nginx changes):

| Step | Action |
| --- | --- |
| 1 | Protected-runtime handoff to generation 12 (signed `primary-release` attestation, threshold 1) |
| 2 | **Host preflight** (read-only, as the application account, staged r0107 code) |
| 3 | Database checkpoint (`pg_dump`) |
| 4 | Guarded migrations, in order: `production.0001_initial` (new tables), `library.0089_voicetrack_media` (nullable `VoiceTrack.media`) — both additive |
| 5 | Checkout fast-forward r0106 → r0107 |
| 6 | `collectstatic` (new `production/iportal/*.js` assets served by nginx from `staticfiles/`) |
| 7 | Units: install changed `isadoraair-gunicorn.service` and new `isadoraair-validation.service`; one `daemon-reload`; `enable --now isadoraair-validation` (starts on r0107 code) |
| 8 | Restart `isadoraair-gunicorn`, then `isadoraair-engine` (engine VoiceTrack media resolution changed) |
| 9 | Postflight: checkout identity, clean schema, Gunicorn HTTP health |

Not restarted: `isadoraair-encoders`, `isadoraair-monitoring`,
`isadoraair-rbds` (none imports anything r0107 changes; the schema change is
additive). The `.env` needs **no edit**: without
`PRODUCTION_VALIDATION_MAX_ACTIVE`/`_MAX_PENDING` the defaults 2/4 apply
(optional keys are documented in `.env.example`). The ProductionMedia root
(`/srv/isadoraair/production-media` by default) is created by the runtime on
first use with its accepted layout (`media/`, `incoming/`, `work/`, `locks/`,
all `0750`, application account); no operator step.

### Host preflight

Registered against `production.0001_initial` in the target's
`updatecenter_migration_preflight` (`production/services/host_capability.py`),
run before the checkpoint, any migration, the checkout advance, any unit
install or start:

- `production.0001.validation_host_capability`: unified cgroup v2; `cpu`,
  `memory`, `pids` available; the kernel provides `cgroup.kill`, `memory.max`,
  `memory.swap.max`, `memory.oom.group`, `pids.max`, `cpu.max`; systemd ≥ 254
  (`DelegateSubgroup=`); a functional sandbox self-test (the launcher's own
  `no_new_privs` + Landlock + seccomp must refuse a write and make `clone3`
  fail with `ENOSYS`).
- `production.0001.media_root_establishable`: `PRODUCTION_MEDIA_ROOT` passes
  `production.root_policy` and is a usable dedicated directory of, or creatable
  by, the application account.

Any failure stops the job `MIGRATION_PREFLIGHT_BLOCKED` with the per-facility
evidence; the application, database, units and services are unchanged.
Limitation: the generation-12 handoff (step 1) precedes the preflight, so on
an unsupported host the station is left on generation 12 with r0106 code —
generation 12 differs from 11 only by the one policy entry, and a retry after
the host is fixed resumes through the runtime-already-authoritative path. The
validation service also keeps failing closed on its own (it never listens
without its boundary).

## Rollback boundary

- Update Center promises **no automatic rollback** (docs/UPDATE_CENTER.md,
  "Failure, retry, and rollback"). Before step 4 a failure leaves the
  application unchanged; between steps 4 and 5 the additive schema stays and
  r0106 code keeps running (the intended recoverable state); after step 5
  failures are `failed`/`manual_intervention_required` with evidence.
- **Schema is forward-only.** There are no reverse migrations. Both migrations
  are additive (new tables; a nullable foreign key), so r0106 code runs
  correctly on the r0107 schema — but once iPortal has been used, VoiceTracks
  bound to ProductionMedia have no legacy file and r0106 code (which plays
  only `filepath`) cannot air them. Rolling the *application* back after real
  use is therefore not a supported operation; the checkpoint dump is the
  disaster-recovery reference for the pre-r0107 database, not a rollback tool.
- ProductionMedia files created after r0107 are permanent and backed up; an
  older checkout simply ignores them.
- Protected runtime: generation 11 stays in the inactive A/B slot as
  last-known-good; the active generation never moves backwards for a new
  candidate (replay/rollback protection).
- `isadoraair-validation.service` and the changed Gunicorn unit would stay
  installed under any manual application rollback; the r0106 checkout has no
  `production_validation_service` command, so the validation service would
  crash-loop harmlessly until r0107 is reinstated or it is disabled by hand.

## Post-install acceptance checklist (KOGR) — not executed during packaging

Identity
- `/opt/isadoraair` HEAD is exactly the published r0107 SHA, clean; local
  `main` advanced only by Update Center; Update Center reports the job
  succeeded and healthy.

Protected runtime
- Generation 12 active, descriptor
  `7dbe7e31cb10593d3b52fe094feb5a8ee7dcbd9a37597b465f014cac002a3ee8`;
  generation 11 retained as previous; `manage.py validate_protected_runtime_release`
  passes; the active policy lists `isadoraair-validation.service ENABLE_NOW`.

Validation service
- `systemctl status isadoraair-validation` active/running; `NRestarts=0`.
- `/run/isadoraair-validation/` is `0700`; `validator.sock` and
  `admission.json` are `0600`; `admission.json` reports `2`/`4`.
- `<unit cgroup>/supervisor` and `<unit cgroup>/iportal-validation` exist;
  `cgroup.subtree_control` lists `cpu memory pids`; no `run-*` leaf at rest.
- One real validation succeeds (below).

ProductionMedia
- After the first upload/recording: the root and its four directories exist,
  `0750`, application account; the media file is `0440`.
- Upload → validation `valid`; preview/range playback works.

iPortal / VoiceTrack (controlled; never disturb on-air material)
- Open the evergreen VoiceTrack recorder; record a short test take; stop and
  preview; make one harmless edit; save/bind.
- Confirm the take validated and the VoiceTrack points at its ProductionMedia.
- Audition through a safe test path only.
- Re-record/repoint; confirm the previous take is unchanged (immutable).
- Delete the test VoiceTrack; confirm the media bytes remain.
- Confirm one existing legacy-filepath VoiceTrack still resolves.

Admin
- Production media → Validation limits shows 2/4 and "Running configuration
  matches saved configuration". The restart-required indication can be
  verified without changing production limits (it is regression-tested).

Backup / DR (immediately afterwards — r0107 is not operationally closed until
these pass)
1. Verify the install succeeded (above).
2. Verify generation 12 is active and accepted.
3. Build a fresh Runtime Recovery payload against generation 12:
   `sudo venv/bin/python manage.py prepare_runtime_recovery_payload --plan --phase-d --base-root /var/lib/isadoraair/runtime-recovery`
   (must report generation 12 *active*, 11 *previous*), then `--apply --phase-d`.
4. Activate it: `... prepare_runtime_recovery_payload --activate --base-root /var/lib/isadoraair/runtime-recovery --payload-id <id>`.
5. As the service user: `venv/bin/python manage.py validate_runtime_recovery_payload --base-root /var/lib/isadoraair/runtime-recovery --current --json --require-current-station-policy`.
6. Keep the previous generation-11 payload (`payloads/phase-d-runtime-recovery-20261004T222048Z`) as the `--activate` rollback target.
7. Run the normal backup (`isadoraair-backup.service`).
8. Run the round-trip verification (`isadoraair-backup-verify.service`, `deploy/verify_backup_roundtrip.sh`).
9. Confirm Recovery Assurance (`/monitoring/`, `backup_recovery_assurance`) is healthy.

Until step 5 passes, the nightly backup fails closed by design (the
activated payload still captures generation 11 while the checkout declares 12).

## Deferred (not in r0107)

- `isadoraair-validation` is not in the protected restart allowlist
  (`RESTART_ORDER`/`CORE_RESTARTABLE_SERVICES`): a later release that changes
  validation code cannot restart it through `services_requiring_restart`
  without a protected-runtime change, and an Admin limit change needs an
  operator restart.
- The updater's post-start check reads `ActiveState` immediately after
  `enable --now`; a `Type=simple` service that fails readiness a second later
  would still pass it. The host preflight removes the known causes; the
  checklist above verifies the socket and limits. A `Type=notify` readiness
  signal would make the updater's check exact.
- Monitoring has no dedicated health check for `isadoraair-validation`.
