# r0129: Operator-Reviewed Duplicate Disposition

r0129 adds an explicitly manual resolution route to the existing Library Reconciliation duplicate
workflow. An authorized **Manage tracks** operator may review a likely or uncertain duplicate
finding, select two Tracks, choose which recording survives, and explicitly acknowledge that the
recordings have not been proven identical.

Nothing is selected or deleted automatically. The operator's decision is editorial authority, not
audio evidence: the retained and deleted Tracks may be different recordings, edits, masters,
performances or audio quality.

## Three separate resolution authorities

The report, preview and audit preserve three distinct authorities:

1. `exact_bytes` — the scanner proved that two complete source files have identical bytes.
2. `decoded_audio` — the scanner proved that two complete files decode to identical canonical audio.
3. `manual_editorial` — the operator reviewed the finding and explicitly chose a survivor without
   asserting that the audio is equal.

A likely or uncertain label, matching metadata, similar duration or shared ISRC is never converted
into proof. The finding retains its original confidence and the audit records
`manual_editorial`.

## Deliberate operator choice

The manual route offers **Keep Track A / delete Track B**, **Keep Track B / delete Track A**,
**Keep both (not duplicates)** and **No action**. No action remains the default. A destructive
choice requires a separate manual-editorial acknowledgment. If the discarded Track has VoiceTracks,
their deletion requires its existing, separate acknowledgment as well.

The operator may explicitly transfer selected *additional* categories to the survivor. The
survivor's primary category is unchanged. No other information is merged: metadata, cue markers,
play history, requests, readiness, waveform state, rotations, log entries and VoiceTracks remain
attached to their original Tracks.

Apply remains one deletion per request. Preview and apply use a short-lived, signed,
operator-bound, single-use token. A lost or uncertain apply response stops the browser sequence;
the browser never retries an irreversible request automatically.

## Complete group evidence and serialization

For a manual deletion, a current reconciliation report must contain exactly one complete,
consistent scan-time file record for **every** member of the duplicate group, up to the existing
25-Track bound. A missing, malformed, duplicated, foreign, shared-inode, protected, non-canonical or
otherwise unsafe member makes the entire group review-only for destructive manual actions. Keep Both remains
available.

Reports created before r0129 do not contain this complete evidence and cannot authorize a manual
deletion. Run a fresh reconciliation scan before using the feature. Installation itself does not
start a scan.

Apply locks every existing Track row in the bounded finding in ascending ID order, in one database
transaction and within the existing lock budget. While holding those locks it reloads and rechecks
the report, evidence, pair and exact previewed membership. A concurrent deletion, new report,
changed file, category change or unavailable group member produces a busy, stale, blocked or
refused result without a partial change. The group must be reviewed again after each deletion.

## Existing deletion and playout safeguards remain authoritative

The r0127/r0128 protections still revalidate the Track rows and files, current and future playlists,
rotations, requests, current/upcoming/active logs, live decks, engine queue and recent claims and
plays. Protected references or active playout block deletion. Category additions and database
deletion commit together; source cleanup runs through the existing commit-safe deletion service and
reports whether the file was removed or safely retained.

Manual acknowledgment overrides none of these protections. It authorizes only the operator's
choice between the explicitly selected files.

## Deployment declaration

* **Migration:** none; no migration-authorization companion exists or is required.
* **Python requirements and APT packages:** unchanged.
* **Systemd and protected runtime:** no unit, timer, policy, descriptor, attestation or protected
  generation change. `protected_runtime` is `null`, so no offline release signature is created.
* **Static and nginx:** unchanged; no `collectstatic` action.
* **Restart:** Gunicorn only (`isadoraair-gunicorn`).
* **Not restarted:** engine, encoders, Monitoring, RBDS, Active Messages, reconciliation processes,
  spoken rendering and every other station service.

Publishing r0129 does not authorize installation at KOGR or WRJE, a production reconciliation
scan, a duplicate decision or deletion of production media. See
[r0129_installation.md](r0129_installation.md).

## Not completed by this release

r0129 does not complete all of roadmap 3.11. Category drift and other independently tracked Library
remediation remain open. This release adds no automatic deletion, perceptual matching, metadata
merge, group-wide destructive operation, scanner daemon, scheduler, engine, encoder or playout
change, and it does not activate Hour Refill or native Active Messages airing.
