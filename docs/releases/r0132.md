# r0132: fairer end-of-hour music and isolated Remote DJ failures

r0132 makes two independent improvements. It adds no setting, migration or service, and it does not change schedule
clocks or rules, how requests are handled or how Remote DJ connects.

## Fairer end-of-hour music rotation

As an hour nears its end, IsadoraAir has to choose music that also lands the hour on time. Previously the last
music slots were planned one or two at a time. Long tracks therefore won the final slot far more often than their
rotation weight justified; for example, a long Pre-70 title repeatedly closed the 6 PM hour.

r0132 plans up to four consecutive music slots together. Among combinations that land the hour, each track keeps a
chance in proportion to its normal effective rotation weight, so closing slots are shared fairly. Each music run is
planned on its own, so a run never inherits planning state from an earlier one.

Unchanged:

- normal (mid-hour) selection, artist/title separation, recency, holiday rules and category identity;
- non-music landing slots (IDs, promos, PSAs), which keep r0131's matched-pair behavior;
- direct inserts, which keep their place and their ordinary hour-boundary handling;
- hour and segment termination, and how a slightly long or short hour is absorbed;
- Web Requests, which may still replace any eligible scheduled music item;
- r0131's DST fall-back replay.

New hours are built with the new planning by the engine's automatic build and by the admin Build/Rebuild page.
Hours already built are not rebuilt. The build summary records two extra counters (`lookahead_picks`,
`landed_unused_slots`). A lookahead miss beyond the existing tolerance raises the existing scheduler-attention
event, as a missed landing pair already did.

## Remote DJ failures are isolated from playout

On November 8, 2026, a Remote DJ connection at WRJE failed during ICE checking. The station muted and retired the
session, but the cleanup never finished. Every later connection was refused as busy, and at the next engine stop
systemd needed SIGKILL after 90 seconds. The cause was in the engine: it tore the session down from inside the WebRTC
component's own callback thread, which then waited for itself forever.

r0132 changes what happens when a Remote DJ session fails, is closed or disconnects:

- The remote microphone is muted immediately and the persistent Remote DJ channel switches to silence. The session
  is retired at once, so a late message from it cannot affect a newer session.
- Cleanup of the session's audio components never runs on the WebRTC callback thread or blocks the engine. The
  components are first disconnected from program audio, then shut down by one bounded background worker.
- **Successful cleanup** frees Remote DJ for the next connection, normally within a fraction of a second. A
  reconnect attempted during that moment is refused with "previous session cleanup in progress"; try again.
- **Failed or blocked cleanup** (an error, or no completion within 10 seconds) quarantines Remote DJ. Program audio
  is unaffected because the components are already disconnected and the channel stays silent. Monitoring raises a
  critical event, "Remote DJ cleanup failed; Remote DJ unavailable until engine restart" (or "... blocked; ..."),
  naming the attempt. New connections are refused with "previous session cleanup failed or blocked; engine restart
  required".
- **A quarantine never restarts the station automatically.** Restarting the engine briefly interrupts playout, so an
  operator chooses when to do it. Until then, automation, the local microphone and everything else continue
  normally; only Remote DJ is unavailable.
- An engine stop no longer waits on a stuck Remote DJ cleanup.

Unchanged: Remote DJ sign-in, admission and permissions; Auto/Manual ownership and the PTT policy; Emergency Mute and
administrator kick; the reconnect grace period; codecs and network settings; and the persistent Remote DJ mixer
channel.

## Deployment declaration

There are no migrations, migration companion, packages, Python requirements, collectstatic, nginx, systemd units or
protected-runtime changes. `protected_runtime` is `null`, so no protected descriptor, policy generation, offline
release signature or attestation is created. The trusted updater restarts Gunicorn and then the engine. Monitoring,
encoders, RBDS, Active Messages and spoken rendering are not restarted. KOGR and WRJE each need separate installation
authorization; see `r0132_installation.md`.
