# r0124: one safe waveform reanalysis workflow

r0124 simplifies roadmap 1.21's operator workflow without changing playout, decoding,
fingerprinting, source media or cue-marker authority. **Reanalyze Track** is now the single
operator-facing action for regenerating a Track waveform and recalculating eligible Cue In and
Next Start markers. The separate **Refresh Waveform Only** command, API, worker and browser polling
workflow are retired.

## Reanalysis behavior

- A Track with a finite, positive stored duration through 900 seconds is analyzed immediately.
- A longer Track, or one with a missing, zero, negative or non-finite duration, records an
  `analysis_requested_at` request and returns **queued**. The existing
  `isadoraair-analyze.timer` invokes the existing analyzer; no unit or timer changes in r0124.
- A queued response means the analyzer will attempt reanalysis. It is not a completion or success
  result, and the page does not redraw the waveform while merely acknowledging the request.
- A completed background attempt clears the matching request timestamp. An interrupted process
  leaves the request for a later timer pass. Existing analyzer diagnostics and journal output show
  failures; r0124 adds no frontend job-completion tracker.
- Explicit marker overrides are refused for queued requests rather than silently discarded.

The analyzer still uses the existing category thresholds and may recalculate only Cue In and Next
Start. Locked, historical and needs-review values remain protected. Optimistic marker revisions
ensure an operator edit made while analysis is running wins, and approval history remains
append-only. The other six markers are never calculated by this action.

## Waveform results and integrity

The response distinguishes what actually happened:

- **verified**: a displayable waveform was installed and the decoded audio identity is trusted;
- **unverified**: a displayable waveform was installed, but strict audio identity was unavailable;
- **not regenerated**: no displayable replacement was installed.

A playable file can therefore have a useful waveform without becoming trusted. Track 35884's
documented invalid-sync scenario demonstrates that limitation: reanalysis can display the waveform
while strict decoded-audio identity remains unavailable. r0124 does not promise that every playable
file will become trusted.

An incomplete stereo decode is never published as a replacement waveform. Cache publication and
rollback protections remain in force, and operator errors are bounded and path-redacted. FFmpeg
arguments, decoding tolerance, audio fingerprinting, WAV/AIF-to-FLAC conversion and source-media
handling are unchanged.

## Monitoring

Routine cue-marker events whose dedupe key starts with `library|cue-markers|` are omitted from the
Monitoring dashboard's Recent Events list and its category choices before the 100-row limit is
applied. The underlying `SystemEvent` rows and cue-marker approval history are not deleted or
changed. Other Library warnings and operational errors remain visible.

## Deployment declaration

r0124 has no migration, migration companion, collectstatic, dependency, package, systemd-unit,
nginx or protected-runtime change. Update Center restarts only `isadoraair-gunicorn`. The analyzer
loads the new command code on its next ordinary timer invocation. Publication does not authorize
installation at KOGR or WRJE.
