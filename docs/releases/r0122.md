# r0122: test isolation (roadmap 1.21)

r0122 keeps the test suite away from a station. A 2026-10-29 incident had tests overwrite
165 real waveform files through the development `.env`; the waveforms were regenerated
from source audio and the cue points were never touched. This release makes a repeat
impossible on a station host and adds a read-only diagnostic for the same failure.

Changes since r0121 are tests, test tooling and documentation only. Nothing a station
runs behaves differently.

## What changes

- **Tests run only inside a kernel sandbox.** `production/tests/run_with_validation_service.sh`
  runs every test process, and every child it starts, in bubblewrap. The sandbox has no
  station storage mounted, a private `/run`, `/tmp` and network, a disposable PostgreSQL
  server for the run, and no access to the systemd user manager or the production database.
  `manage.py test` run any other way refuses to start (`KERNEL_SANDBOX_MISSING`).
- **A fail-closed write guard inside the sandbox.** Station storage, the live checkout,
  `/etc/isadoraair` and the station runtime trees (`/run/isadoraair*`, including the
  updater and service sockets) are refused for every write, rename, delete, descriptor
  write and Unix-socket connect. A refused write fails the run even if the code under
  test swallowed the error.
- **Test-fixture corrections.** Tests that had reached live state outside the sandbox now
  use private scratch or stubs: RBDS and monitoring state files, encoder classifier and
  candidate scripts, the engine command queue, the updater socket, the Liquidsoap telnet
  port, `systemd-tmpfiles`, and fixed shared waveform directories.
- **`manage.py check_waveform_integrity`.** A read-only diagnostic that lists waveform
  JSON which cannot be a genuine analysis of its track. It never writes a file or the
  database, and scanning a station directory requires `--allow-production-read`.
- **`manage.py test_isolation_preflight`.** Prints the effective test roots and proves the
  eleven protected-path probes are refused. It refuses to run outside the sandbox.

## What does not change

- `isadoraair/settings.py` only gains an appended block. For every process except
  `manage.py test` and the test runner's own services, the effective settings are
  identical to r0121 except `TEST_RUNNER`, which only `manage.py test` reads.
- No migration, companion, static file, template, systemd unit, package, nginx, dependency
  or protected-runtime change. The protected updater stays at generation 15.
- No service restart is needed, and none is declared.

## Qualification

All 17 application suites ran inside the sandbox at `928cc37`: 9,674 of 10,421 selected
tests passed, and containment held in every run. That is **not** a pass of the whole
application suite. Media-validation tests cannot pass in this same-host sandbox. Browser
and systemd-dependent tests are excluded. Some historical failures remain. See
`docs/TEST_ISOLATION.md` for the results, the exclusions and the sandbox limits; improving
them is separate follow-up work.
