## What changes

All three refinements are implemented once in the shared, domain-neutral
iPortal workstation, so every recorder domain — produced content (REGULAR
and TEST / NO AIR), evergreen VoiceTrack and active-message drafts — gets
the same behaviour.

- **Calibrated input meter.** The console's VU scale instead of a linear
  percentage: the station's `AudioPipeline.vu_meter_min_db` (−40 dBFS by
  default) to 0 dBFS, green below −20 dBFS (0 VU), yellow to −6 dBFS, red
  above (50 % / 85 % on the default scale, recomputed for any other minimum).
  The bar is the **RMS** level; a thin marker is the **peak**, held 300 ms
  then falling 20 dB/s like the engine's meter; both are labelled. The meter
  settles to "no input" when the microphone is released or lost. Set Level,
  the gain and the captured audio are unchanged.
- **Preview transport.** One **Preview / Pause / Resume** button and
  **Stop**. Pause keeps the playhead; **Stop and a natural end** (of the
  clip or of the selection, which is never passed) return the playhead to
  exactly 0 and keep the selection; a click on the waveform seeks during
  preview. Recording, punch-in and editing still use the playhead exactly as
  before.
- **Waveform navigation.** Wheel zooms around the cursor; a sideways
  trackpad swipe or Shift + wheel scrolls; Ctrl + wheel (trackpad pinch)
  zooms. Touch: tap places the playhead, one-finger drag selects, two-finger
  pinch zooms and two-finger drag scrolls. Vertical page scrolling stays
  native; navigation never edits audio.

The only server-side change: the workstation view passes the meter minimum
to the page, read without writing (it never creates the `AudioPipeline`
row; a missing or invalid value falls back to −40).

## Update Center sequence

1. Fetch trusted source.
2. Validate the r0114 plan (r0113 → r0114) and stage its exact immutable
   target.
3. No migration: no companion, no database checkpoint is needed for schema.
4. Advance the checkout to the immutable r0114 target.
5. Run `collectstatic` (the three iPortal scripts changed).
6. Make no systemd reconciliation changes.
7. Restart `isadoraair-gunicorn` only (the workstation view and template).
8. Run postflight checks (exact checkout, clean schema, Gunicorn health) and
   clean staging.

Not restarted: the engine, spoken render worker, render and validation
services, monitoring, encoders and RBDS — nothing they run changed.

Failures before the checkout leave the live application unchanged. After
it, Update Center records failure evidence and the operator fixes forward;
there is no automatic rollback. r0113's forward-only rule still applies: a
code-only return to r0112 is never supported once TEST / NO AIR media may
exist (docs/releases/r0113.md).

3. A recent backup with a passing round-trip and Recovery Assurance `ok`.

   it).

## Post-install acceptance checklist (not executed during packaging)

Each step passes only as stated.

### Identity
- Job succeeded; installed release r0114; HEAD is the r0114 release commit,
  clean; only `isadoraair-gunicorn` restarted; generation 14 still active;
  no migration pending.
- The served `workstation.js`, `recorder.js` and `audio_core.js` are the new
  versions (hard-reload a recorder page; the meter shows a dBFS scale).

### Meter
- Open any recorder workspace, enable the microphone: the scale reads −40,
  −20, −6, 0 (or the station's minimum), the bar moves with speech, the
  marker holds peaks; normal speech sits mostly green-to-yellow, shouting
  reaches red. Releasing the microphone (e.g. pressing Preview) empties the
  meter. Set Level still sets the gain as before.

### Transport
- Preview → Pause → Resume continues where it paused; Stop and the natural
  end return the playhead to 0; with a selection, preview stops at the
  selection end and keeps the selection.

### Navigation
- Wheel zoom follows the cursor; Shift + wheel or a sideways swipe scrolls;
  on a phone or tablet, pinch zooms and two fingers scroll, a tap moves the
  playhead, and the page still scrolls vertically.

### Unchanged behaviour
- In at least one workspace of each kind in use (a produced-content TEST
  take, a regular submission, a VoiceTrack), saving or submitting behaves
  exactly as in r0113. TEST takes remain unairable.
- On-air audio, engine, encoders and monitoring are unaffected (no restart).

## Known limitations

Verified in headless Chromium (mouse, wheel, real multi-touch via the
DevTools protocol); Safari, Firefox and physical iOS/Android devices were
not exercised. The zoom anchor cannot stay exactly under the cursor where
the clip edge clamps the view. A vertical two-finger drag scrolls the page
rather than the waveform, by design.
