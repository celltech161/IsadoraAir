## Release notes

### New

- **Native REGULAR produced content** — a station-defined *regular*
  `ProducedContentType` becomes producible in iPortal through an explicit,
  managed Phase-C `SpokenContentType` backend (generated identity
  `produced-<uuid>`; never matched by key, code, name, category or recipe).
  Items use the existing Phase-C lifecycle, the existing leased
  `isadoraair-spoken-render-worker`, the existing `isadoraair-render` service,
  one of the five existing code-backed recipes (`cal_events`, `usd239min`,
  `news_item`, `3min_ctr`, `lcl_psa`), the existing projection and atomic
  library promotion. Output: an ordinary Ready-to-Air FLAC Track in the type's
  category (*single* → current edition, *accumulating* → one Track per item).
  No new renderer, worker, playout lane, engine command or priority insertion.
- **My Content** — `/iportal/content/`: a producer's assigned enabled regular
  and TEST types, their items and states; Start, Submit for processing,
  Abandon / Withdraw / Recall with a confirmation that carries the expected
  state (checked under the lifecycle's own locks: a stale confirmation
  changes nothing). Station control (`active_message.control`) sees and
  manages every producer's items of managed regular types, read-only in the
  recorder; another producer's item is never disclosed (404).
- **Shared recorder adapter `produced-content`** —
  `/iportal/content/record/` (`?item=<uuid>` or `?test_type=<key>`), API under
  `/iportal/content/api/recorder/`. The subject is resolved server-side; only
  the item's own producer writes. Submission is one transaction with an
  optimistic revision (a stale second tab gets 409); nothing renders in the
  request.
- **TEST / NO AIR workspace** — a private practice take per (user, TEST type),
  saved, replaced or removed in the recorder ("TEST / NO AIR — Nothing in this
  workspace can air."). Fixed retention: **7 days after the most recent
  save**; the existing spoken worker sweeps expired takes at most once a
  minute, 100 per pass, isolated from rendering.
- **Immutable no-air media provenance** — `ProductionMedia.airing_prohibited`.
  Every take the TEST recorder makes (record, import, edit; saved or not) is
  stamped at intake from the server-resolved subject; every derivative
  (edits, renditions) inherits it; the model refuses a child that drops it and
  a derived row whose parent does not already exist. The canonical
  air-capable binding (`production.services.retention.lock_for_binding`)
  refuses it, so regular submission (HTTP, service and spoken API, owner or
  manager), rendition delivery, VoiceTrack, active-message media and
  aggregates, and reference audio all refuse TEST media — while it is a take,
  after it is replaced, discarded or expires, and whatever keeps its bytes.
  Only the TEST binding (`lock_for_no_air_binding`, which requires no-air
  media) and derivation intake (`lock_parent_for_derivation`) handle it.

### Feature gates and defaults (nothing is switched on)

- `NATIVE_AIRING_AVAILABLE` stays `False`; no active-message worker or service.
- **No station data is seeded**: no produced-content type, assignment or
  backend is created. Until an administrator configures a regular or TEST
  type and assigns producers, My Content offers nothing to produce. The five
  recipe names are recipe identities, not installed workflows.
- Capabilities are the existing `active_message.produce` /
  `active_message.control` (r0110: Station Administrator only); no new role or
  capability.
- OGRemote is untouched (no import of its rows or files).

### Not included

D3D (operator Active Messages board, Replay Now), D3E (monitoring/history,
active-message worker packaging), any cutover / OGRemote retirement, legacy
import, Phase E (talent assignments, work queues, legacy-user migration), new
GStreamer paths, engine commands, renderer or validation protocol changes,
configurable TEST retention.

## Migrations

From an r0112 schema the target plan (the real `updatecenter_probe`
classifier over the exact on-disk migrations; all four atomic) is, in order:

| # | Migration | SHA-256 | Operations | Classification |
| --- | --- | --- | --- | --- |
| 1 | `produced_content.0002_d3c_spoken_backend_and_test_take` | `5efdbdc1c5c9ed279aeaae492794d8870cf4e5829d710e0cbd6b133cdde96d52` | 0 AddField `spoken_content_type` (nullable OneToOne), 1 CreateModel `ProducedContentTestTake` | additive, additive |
| 2 | `produced_content.0003_recipe_key_leading_digit` | `4d699999e8e30b891352c41126b7527a2946262495b19a22db252c324b3b7d78` | 0 RemoveConstraint, 1 AlterField (`recipe_key` validator), 2 AddConstraint (`^[a-z0-9][a-z0-9_]{0,63}$`) | **manual ×3** |
| 3 | `produced_content.0004_backend_regular_only` | `ae11abee01664d779b9643210d6a61fdde333810fa3313a870beef76f5a66c7b` | 0 AddConstraint `produced_type_backend_regular_only` | **manual** |
| 4 | `production.0003_media_airing_prohibited` | `bf8b9cb037d2f8703279b6b12e2330af61f27a2991753d40704413b4e145ec89` | 0 AddField `airing_prohibited` (non-null boolean, `default=False`, `db_default=False`) | **manual** ("non-null AddField uses database default") |

`migration_compatibility` is `additive`: nothing is dropped or rewritten.
0003 only widens a pattern every existing row satisfies (so `3min_ctr` is a
legal recipe key); 0004 only guards what the bridge already guarantees;
`production.0003` adds a column every existing row satisfies as `false`. No
data migration, no seed, no authz migration.

**The database default is deliberate and required.** The updater migrates
before it advances source and restarts services, so r0112 Gunicorn and the
r0112 spoken worker keep inserting `ProductionMedia` without the new column
during that window. PostgreSQL keeps `DEFAULT false` (`ADD COLUMN
"airing_prohibited" boolean DEFAULT false NOT NULL`, no `DROP DEFAULT`), so
those inserts succeed and are air-eligible, as r0112 media always was. Never
"simplify" it away to obtain an additive classification.

### Trusted migration authorization

The **five** manual operations — `produced_content.0003` #0, #1, #2,
`produced_content.0004` #0 and `production.0003` #0 — are covered by the
trusted companion `deploy/migration_authorizations/r0113.json`, introduced by
its own single-parent, metadata-only commit after the release commit. It binds
`release_id`, the release commit, the SHA-256 of this manifest's committed
bytes, and each migration file's exact SHA-256 (docs/UPDATE_CENTER.md,
"Trusted companion migration authorization"). A station whose plan contains
exactly these operations needs no local approval; any other plan falls back to
exact station-local approval. The companion carries no signature: like every
application release it inherits the trust of the root-configured,
fast-forward-only trusted repository.

Planned by Update Center from r0112:

| Step | Action |

| 1 | No protected-runtime handoff — generation 14 remains active |
| 2 | Stage the exact r0113 release target |

**Restarts and why:** Gunicorn serves every changed web surface (URLs, views,
templates, admin, recorder, produced-content and production services). The
spoken render worker runs the changed command (the TEST-take expiry sweep)
and the changed spoken transitions, delivery and rendition intake. r0112 added
the worker to the protected restart allowlist precisely for this release.

**Not restarted, deliberately:** `isadoraair-engine` (it loads
`active_messages.services` only through `active_messages.playout`, which calls
no media binding; `production.errors` gained classes only),
`isadoraair-render` and `isadoraair-validation` (their code is unchanged;
rendition intake runs in the worker), `isadoraair-monitoring` (imports only the
unchanged render/validation health modules), `isadoraair-encoders`,
`isadoraair-rbds`. Unrestarted processes keep reading `ProductionMedia`
normally (selects name their columns) and never insert it.

## Forward-only release and recovery

> **r0113 is forward-only once TEST media may have been created. A code-only
> rollback to r0112 is not supported.** r0112 code does not know
> `airing_prohibited`: its media bindings would accept TEST / NO-AIR media.
> Never reset Git, check out r0112, or restart r0112 services against a
> database r0113 has used. A true pre-upgrade return requires restoring the
> application code **and** the database together from a compatible
> pre-upgrade checkpoint through the station's approved recovery process.

What the protected updater actually does (docs/UPDATE_CENTER.md, "Failure,
retry, and rollback"; it promises **no automatic rollback**):

| Failure point | State and supported handling |
| --- | --- |
| Before migration (steps 1–4) | Production unchanged. Fetch, validation and staging are repeatable; retry. |
| During migration (step 5) | Each migration is one guarded atomic transaction with a root-recorded receipt; partial-prefix recovery resumes exactly after the owned prefix. An ambiguous interruption cannot auto-resume: manual intervention with evidence. |
| After migration, before source advancement (steps 5–6) | Expanded additive schema with r0112 source still running — the intended recoverable state. r0112 keeps working (its `ProductionMedia` inserts get the database default). Retry the update or fix forward; no TEST media can exist yet (r0112 has no TEST workspace). |
| After source advancement, before or during restarts (steps 7–9) | No automatic rollback: `failed` / `manual_intervention_required` with evidence; completed restarts are skipped on retry, an ambiguous interrupted restart is manual. Fix forward. |
| After restart / postflight | Installed. Fix forward with a corrected release. |
| After r0113 has accepted TEST media | Forward-only (above). |
| Full pre-upgrade restoration | Only as a disaster-recovery action restoring code and database together from the step-4 checkpoint (or the pre-update backup) through the approved recovery procedure, with Recovery Assurance afterwards — never a code-only revert. |

## Post-install acceptance checklist (not executed during packaging)

Each step passes only as stated; any failure stops acceptance.

### Identity and updater
- Job succeeded; installed release r0113; HEAD is the r0113 release commit,
  clean. Only `isadoraair-gunicorn` and `isadoraair-spoken-render-worker`
  restarted (their `ActiveEnterTimestamp` advanced; engine, render,
  validation, monitoring, encoders, rbds unchanged). Generation 14 still
  active. `showmigrations` shows the four migrations applied, nothing pending.
- Schema: `airing_prohibited` is `boolean NOT NULL DEFAULT false`; every
  pre-existing `ProductionMedia` row is `false`.

### Broadcast and services (no live interruption)
- Engine playing scheduled music; segues normal; audio output and processing
  chain unchanged; encoders and stream healthy; RBDS/metadata updating;
  monitoring all green; Remote DJ and microphone readiness checks pass
  without going live.
- Gunicorn `/healthz/` `ok`; spoken worker running with no repeated errors in
  its journal; validation service ready; no resource growth over an hour.

### Produced content (safe, non-airing)
- With no types configured, `/iportal/content/` loads for an authorized user
  and offers nothing; the hub shows My Content only to producers/control.
- Optional, with a disposable TEST type assigned to a test user: the TEST
  recorder shows TEST / NO AIR; a recorded take saves, replaces and removes;
  in the admin its `ProductionMedia` shows `airing_prohibited = true`, and an
  edit of it is also `true`.
- **NO-AIR acceptance**: committing that TEST media to a regular draft (if a
  disposable regular type exists) is refused (`airing_prohibited`), and it
  cannot be bound as a VoiceTrack, active-message media or reference audio.
  Do not create a live Ready-to-Air Track to prove a negative; the
  engineering suites prove the refusals.
- Optional, only with a deliberately configured regular type in a non-airing
  category: an ordinary submission renders and delivers one Track; withdraw /
  recall then removes it. Leave no test Track Ready-to-Air.
- Remove disposable test types/assignments afterwards; TEST takes expire in
  7 days or can be removed.

### Recovery assurance
- Run the existing post-release backup, remote round-trip verification and
  Recovery Assurance; refresh the Runtime Recovery payload only if the
  existing procedure requires it (the protected runtime did not change).

## Known limitations and deferred work

- Same-batch derivations of `ProductionMedia` are refused outright (nothing
  uses them). Django's plain `models.QuerySet` and raw SQL remain outside the
  application boundary, as for every `ProductionMedia` invariant.
- Deferred, non-blocking: `spoken/tests/test_migration.py` keeps a stale test
  name/comment narrative; a few already source-verified ORM variants lack a
  direct regression test.
- Phase E, D3D, D3E and the OGRemote cutover are separate releases.

## Evidence required before declaring production acceptance

The completed identity, broadcast, produced-content and NO-AIR checks above;
the post-release backup, round-trip and Recovery Assurance results; and the
Update Center job evidence. Engineering acceptance is not production
acceptance.
