## A — Evergreen Voice Track transitions

On 2026-11-16 KOGR skipped an intro Voice Track because VT entry was evaluated only from the outgoing song's Outro
Starts marker; the outgoing had none. r0145 replaces the r0144 VT state machine with a two-sided transition planner:

- **Two sides.** An outgoing song's **outro VT** and the incoming song's **intro VT** are planned independently. A
  missing marker on one side no longer suppresses the other. An outro VT needs a valid Outro Starts (otherwise it is
  suppressed with a reason). An outro VT whose Outro Starts lies at or beyond the ordinary segue never delays the
  transition.
- **Underlap and vocal boundary.** A short intro VT starts with the audible incoming music. A long one starts first and
  the incoming music is delayed so the whole VT ends before Intro Until with a fixed **150 ms** vocal safety margin.
  With no usable Intro Until the whole VT plays, then the margin, then the song. Holds are bounded and always recover.
- **Precedence.** A live studio microphone or Remote DJ suppresses pending VTs and fades active speech in about 50 ms.
  Start Next, manual deck starts and a song started by an operator Eject bypass intro VTs. Start Next during a VT
  cancels it with no double advance and no skipped occurrence. Ejecting the incoming cancels its intro VT. Urgent
  Weather/AMBER and dedication speech keep r0137 priority; evergreen VTs never attach to them.
- **Actual-audio admission.** The incoming song becomes on air (and `played_at` is recorded) from deck-mixer evidence
  of its own audio, not from a timer. VoiceTrack lookups run on a worker thread, never on the audio thread; an
  unavailable lookup falls back to the ordinary segue.
- **Dedicated VT ducking.** Music is ducked under VT speech and released at speech end or cancel. The complete VT head
  and tail are played.
- **Durable teardown.** Every retired VT branch is owned by the bounded teardown coordinator until GStreamer confirms it
  stopped. A branch whose stop fails, times out, is abandoned or is refused is **quarantined** for the life of the
  engine process (never released while GStreamer may still use it), and Voice Tracks are **suspended** for that
  process: each later VT fire is refused, program playout continues with ordinary segues, and Monitoring records one
  deduplicated `engine|vt2-teardown|<kind>` event per kind with `voice_tracks_suspended=True` and
  `program_playout_interrupted=False`. With eight VT branches alive or awaiting teardown, new fires are refused until
  the backlog drains. An engine restart
  clears the suspension.
- **State.** `engine_state.json` keeps every r0144 key and adds `vt_transition`. The Hour Refill observer reads the
  new VT phase.

The design and qualification record is in `docs/roadmap/2_25_PHASE_A_VT_TRANSITION_CONTRACT.md` and the B0–B7
documents beside it.

## B — Library filtered CSV export

`/library/` has an **Export to .csv** button. It downloads every Track matching the **filters and sort currently
shown** (search, Category, status, sort column and direction): not only the visible page, and not the checkbox
selection. `GET /api/tracks/export/` uses the same filter and sort code as `/api/tracks/`; it is under the
`/api/tracks/` access rule, so exactly the accounts that can read the Library list can export.

- Columns, in order: `Artist,Title,Album,Category,Duration` (primary Category code; Duration `m:ss`, blank when
  unknown). No file paths or other fields.
- UTF-8 **with a byte-order mark**, CRLF, RFC 4180 quoting. File name `isadoraair-library-YYYY-MM-DD.csv` (station
  timezone).
- Streamed in batches; nothing is held whole and no temporary file is created.
- Formula-injection protection: a text value beginning (after any whitespace) with `=`, `+`, `-` or `@`, or beginning
  with a TAB, CR or LF, gets one leading apostrophe. Nothing else is altered.
- Read-only: **no Library record, audio file, embedded tag or Bulk Edit behavior changes.** Details:
  `docs/LIBRARY_CSV_EXPORT.md`.

## C — NWS alert-fetch failure visibility

When `api.weather.gov` fails, the NWS poll keeps the previous watch/warning snapshot (a retrieval failure is not a
cancellation), and after 15 minutes Weather Health reports it as stale. r0145 says **why**:

- Each NWS poll cycle records its outcome in `WEATHER_DATA_DIR/nws_alert_fetch_status.json`: an `upstream` failure
  (HTTP error, network error, unreadable answer) or a `local` one (NWS answered but this station could not process or
  publish it, for example a full disk). `ok: true` is recorded only after the snapshot was written and renamed into
  place. A failed publication leaves the previous snapshot in place.
- Weather Health appends the cause to the degraded `watch_warnings` summary, for example `The NWS alerts fetch has been
  failing for 14 min (HTTP 503); the last snapshot is kept until it succeeds.` Monitoring's Weather probe adds
  `degraded_details` (and `needs_attention_details`), so Recent Events and notifications show the cause.
- **Recovery:** the next successful cycle records `ok: true` and a fresh snapshot; the fact returns to ready and the
  cause disappears. An invalid, old or contradictory status record is ignored (no cause is inferred).
- The status file is evidence only. It never inserts, replays or cancels an alert. NWS/AMBER alert identity,
  eligibility, replacement, airing, urgent priority and the combined `wx_alert.flac` are unchanged. The AMBER poll is
  unchanged. Details: `docs/WEATHER_ALERT_COMBINED.md`.

## Limitations (accepted; not remediated in r0145)

1. **Inherited playback-continuity limits remain** (roadmap 1.21): no recovery after unexpected power loss; a claimed
   but unaired item is not recovered; long-form outage recovery and the exhausted-hour / live-fill gaps are unchanged.
2. **Ordinary deck limits remain:** the deck-mixer idle freeze (pre-existing in r0144: the first start after several
   minutes with no deck playing can be delayed; during the 4-hour live-fill soak it caused all four dead-air intervals,
   reproduced identically on r0144), ordinary deck tail truncation and ordinary mixer/decoder starvation.
3. **A teardown failure suspends Voice Tracks until the next engine restart.** Program playout continues with ordinary
   segues; Monitoring shows the `vt2-teardown` event. Restart the engine in a maintenance window to restore VTs.
4. Voice Track hardware loopback qualification was reviewed but not run on isolated off-air hardware.
5. Embedded ID3/Vorbis metadata synchronization (roadmap 3.11) is **not** part of r0145. The CSV export reads database
   metadata only.

Not included: roadmap 1.21, 2.6 (occurrence-specific VT jobs), 2.26 (vocal-boundary inference), 2.27 activation
policy (Hour Refill arming is unchanged), native iPortal Active Messages airing.

## Operational impact

There is no migration: `migrations_required` is empty and `migration_compatibility` is `null`. There are no new
packages, Python requirements, static assets, collectstatic, nginx changes, systemd units, manual bootstrap or
protected-runtime changes: `protected_runtime` is `null`. Restart exactly:

1. `isadoraair-gunicorn`
2. `isadoraair-engine`
3. `isadoraair-monitoring`

The engine restart **interrupts program audio** briefly; install in an approved maintenance window. Because the
station already runs r0144, the Update Center applies the **engine restart safeguard** to this installation: it is
refused while a studio microphone or Remote DJ is live or engine status is unknown. Do not override it to install.
The encoders, RBDS and workers keep running. The NWS poller (`wx-update-local-data`) is a scheduled one-shot process
and loads the new code on its next run; no unit or timer changes. After installation, reload open console, `/library/`
and Monitoring pages.

Publication does not authorize installation: each station requires separate preflight, installation authorization and
operational acceptance; see `r0145_installation.md`.
