# r0111 — iPortal live playhead and navigation polish

Predecessor: **r0110**, immutable installed target
`38e0fef801728b01f51df00422767b2c5210dc8c`.

Accepted feature baseline:
`d2da6e9795d81957f54057b5c714dd75b287aec1`.

Protected runtime: **unchanged — generation 13**. The release manifest uses
`"protected_runtime": null`; there is no descriptor, attestation, bootstrap,
runtime or signing change.

## New and polished

- The shared iPortal waveform uses the Track Detail playhead convention: a
  white 2 px line with white triangle tips at the top and bottom, drawn last.
- Browser-local Preview now advances the existing editor `S.playhead` smoothly
  from `AudioContext.currentTime` through one bounded animation-frame loop.
  Manual Stop preserves the reached position, natural playback ends at the
  preview endpoint, and selection Preview traverses the selected interval.
- Click positioning, drag selection and punch-in continue to use the same
  canonical `S.playhead`.
- The main navigation gains an enabled, same-tab **iPortal** entry for
  `iportal-index` (`/iportal/`), at sort order 120. iPortal, My Messages,
  Active Message recorder and Voice Tracking section views highlight it.
- Existing `GroupAccess` filtering remains authoritative. This release adds no
  permission or GroupAccess row.

The browser script is collected and served by nginx. The navigation row is
read by the existing `NavMenuItem` context processor. Consequently r0111 runs
`collectstatic` but requires **no service restart**.

## No broadcast-path changes

r0111 changes no engine, GStreamer, renderer, Active Message lifecycle,
validation or OGRemote behavior. No native-airing worker or service is added.
`active_messages.services.NATIVE_AIRING_AVAILABLE = False`, and legacy
OGRemote remains authoritative.

## Migration and trusted authorization

The exact r0110 → r0111 migration plan is:

```text
library.0090_seed_iportal_nav_item
```

`library.0090_seed_iportal_nav_item` is data-only and contains one
`RunPython` operation. It idempotently seeds the top-level iPortal item by its
durable `iportal-index` URL name. It does not change the `NavMenuItem` schema,
and reversal removes only an untouched product-default row. The mechanical
classifier correctly marks operation 0 (`RunPython`) as `manual`.

The trusted companion at
`deploy/migration_authorizations/r0111.json`, introduced after the immutable
release target in a separate metadata-only commit, authorizes exactly that
operation. It binds r0111's release target, exact manifest bytes and exact
migration-file bytes. Any different or additional manual operation remains
unauthorized.

The migration is backward-compatible with r0110: `/iportal/` and the
`iportal-index` URL already exist there, and an extra navigation row does not
prevent r0110 code from running. Update Center nevertheless retains its
forward/fix-forward semantics; it does not promise automatic rollback.

## Update Center sequence

1. Fetch trusted source.
2. Validate the r0111 plan and stage its exact immutable target.
3. Validate the trusted migration-authorization companion.
4. Checkpoint the database.
5. Apply `library.0090_seed_iportal_nav_item`.
6. Verify the target schema is clean.
7. Advance the checkout to the immutable r0111 target.
8. Run `collectstatic`.
9. Make no systemd reconciliation changes and restart no service.
10. Run postflight checks and clean staging.

Failures before migration leave the live application unchanged. After the
additive data migration, r0110 remains compatible, but Update Center records
failure evidence and the operator fixes forward rather than assuming a source
or database rollback. The pre-migration checkpoint remains a disaster-recovery
reference, not an automatic rollback mechanism.

## Post-install acceptance checklist (not executed during packaging)

### Identity

- The installed checkout HEAD is the unique commit that introduced
  `deploy/releases/r0111.json`, not the later companion commit.
- Published `main` may be ahead at the companion-bearing branch tip.

### Schema

```bash
venv/bin/python manage.py showmigrations library
```

must show:

```text
[X] 0090_seed_iportal_nav_item
```

and:

```bash
venv/bin/python manage.py makemigrations --check --dry-run
```

must report `No changes detected`.

### Navigation row

Read-only Django shell check:

```python
from library.models import NavMenuItem
NavMenuItem.objects.filter(url_name="iportal-index").values(
    "label",
    "url_name",
    "sort_order",
    "enabled",
    "open_in_new_tab",
    "extra_active_view_names",
).get()
```

Expected essentials:

```text
label = iPortal
url_name = iportal-index
sort_order = 120
enabled = True
open_in_new_tab = False
```

### Static and UI

- Over HTTPS (local nginx redirects HTTP), verify
  `/static/production/iportal/workstation.js` is served and contains the live
  playhead implementation.
- As Station Administrator, confirm iPortal appears in the main navigation and
  `/iportal/` opens.
- Open an iPortal recorder/editor containing audio. Confirm the playhead is
  white with top and bottom triangle tips, Preview advances it, Stop freezes
  it at the reached position, and clicking the waveform still positions that
  same cursor.

### Authorization

Do not broaden GroupAccess. A restricted account without `/iportal/`
permission must neither see a usable iPortal link nor gain access merely
because the navigation row exists.

### No restart

Record service activation timestamps before and after installation, or inspect
the Update Center log, and verify r0111 restarted **no services**.

### Native airing and Runtime Recovery

```python
from active_messages import services
services.NATIVE_AIRING_AVAILABLE
```

must remain `False`.

Protected-runtime generation 13 remains active. No Runtime Recovery refresh is
required solely for r0111.
