# r0125: Library integrity, bulk editing and reconciliation

r0125 delivers roadmap 3.11's Library work: safer Track deletion, bulk metadata editing, an
operator-run reconciliation review with duplicate review and explicit relinking, and Library
audit events in Monitoring. It also corrects three documents.

It changes no playout, scheduling, encoder, cue-marker or waveform-analysis behavior. Every new
Library page and API requires the existing **Manage tracks** capability (`library.manage_tracks`).

## 1. Track deletion and post-commit media cleanup

Every Library deletion path now uses one commit-safe service. That covers:
* Track Detail delete;
* the Library list's bulk delete;
* Django admin delete, single and bulk;
* `apply_duplicate_resolutions`;
* `find_orphaned_tracks`;
* the `remove_track_file` recall;
* abandoned dedication intros.

* **Database first.** The Track row is deleted first. Source audio and the waveform cache are removed
  only after that deletion commits. A deletion refused by a protected reference (a playlist, for
  example) or rolled back leaves the Track, its audio and its waveform exactly as they were.
* **A new owner always wins.** Track registration takes a per-path database lock: creating a Track,
  changing its file path, `sync_track_file` and imports. Post-delete cleanup takes the same lock, then
  re-checks under it.
  * A file that another Track now owns is kept.
  * So is a file that was replaced or changed after the deletion.
  * So is a file changed in the last 60 seconds, which may be a delivery in progress.
  * So is a path that is relative, a symlink alias or not canonical.
* **Waveforms.** Only the Track's canonical cache file (`WAVEFORMS_DIR/<id>.json`) is removed.
  * A recorded waveform path that is not canonical is never followed. The cache is kept and logged
    for review.
  * A durable deletion marker (`WAVEFORMS_DIR/.locks/<id>.deleted`) stops a late analyzer run from
    re-creating a deleted Track's cache.
* **Domain-owned media.** Active Messages publications keep their own audio and waveform for that
  domain's retention workflow. A projected spoken Track still detaches its asset as before.
* **Observable, never reversed.** A cleanup that fails or deliberately keeps a file does not undo
  the committed deletion.
  * Track Detail, the Library bulk delete and admin report it.
  * The journal records one line per case:
    `track_cleanup track_id=… operation=… db_deleted=true outcome=… file='<name>' error=…`.
  * Kept files are ordinary orphaned media for later review. Nothing else removes them.

## 2. Library bulk metadata editing

On **Library**, a manager selects Tracks, either by ticking rows or by choosing every result of the
current filter, up to 1,000 Tracks. They then preview a change set.

* **Editing.** Each editable field is *leave* (the default), *set* or *clear*. Additional categories
  and holidays are only added or removed by name.
* **Preview.** The preview writes nothing. It shows the count, each change, refusals, warnings and a
  sample.
* **Apply.** Apply carries out exactly the previewed change. It is one-time and expires after 15
  minutes. It is bound to the operator and session.
  * Each Track is updated in its own transaction.
  * A Track that changed since the preview is reported **stale** and left alone.
  * The result reports every Track as updated, unchanged, refused, stale, missing or failed. A
    partial result is never reported as complete.
* **Retired actions.** The old unreviewed direct bulk actions on `/api/tracks/bulk/` now answer
  **410 Gone**:
  * `ready2air_on` and `ready2air_off`;
  * `set_category`;
  * `add_additional_category`;
  * `add_holiday`.

  The Library page uses preview and apply instead. Bulk **delete** is unchanged and uses the
  deletion service above. No other caller exists in this repository; a station-local script that
  used those actions must move to preview/apply.
* **Never touched:** audio-file tags, cue markers, waveforms, source audio, logs and play history.
  Nothing is reanalyzed. Changing a primary category does not move the file (Track Detail
  relocation remains the way to move a file).

## 3. Operator-run reconciliation (read-only)

`manage.py reconcile_library`, run by an operator as the station service account, compares
`LIBRARY_ROOT` with the Track rows. The report covers:
* missing, moved and unregistered files;
* duplicate, drifted, shared and protected items;
* in-delivery and uncertain items.

The report is written under `REPORTS_ROOT/library-reconciliation/`. Review it at
**Library → Reconciliation** (`/library/reconciliation/`).

* **It writes nothing to the Library.** It changes no Track, file, cue point, readiness, waveform or
  duplicate decision.
* **It deletes, imports and repairs nothing.** A finding is a review item, not an instruction.
* **Nothing schedules it.** Run it outside busy hours. It holds no database or file locks while it
  reads. It refuses to start while another scan is running.

## 4. Duplicate review

Duplicate groups show confidence levels and, for a bounded sample of members:
* file location, size, format and categories;
* the references a deletion would meet.

Large groups show the exact totals.

* **Recorded decision.** An operator can record one displayed pair as **not a duplicate**. It is the
  only decision this release records.
* **Unregistered copies.** Exact byte-identical groups that include unregistered files, with no
  Track, stay visible for review. They are labelled "requires review" and offer no Track-pair
  decision.
* **No removal.** A duplicate is never a reason given for deletion. There is no merge or delete
  control.

## 5. Explicit, evidence-qualified relinking

A missing Track whose audio provably moved to exactly one candidate file can be relinked with
**Review relink…** then **Confirm relink**.

* **When it's offered.** Only when the Track's cached audio identity matches that candidate.
* **How it applies.** The preview shows the exact change and what is kept. Apply uses a signed,
  operator-bound token that expires after 10 minutes. It takes both path locks, then the Track's
  row lock, and re-checks the file, the Track and the identity. Any difference refuses and writes
  nothing.
* **What changes.** Only the Track's `filepath` and `filename`. No file is moved, copied or deleted.
* **Never reanalyzed.** A relinked Track keeps its id, metadata, cue points and approvals, readiness,
  play history and waveform cache.
  * The waveform stays displayable but is shown as unverified until an operator deliberately runs
    **Reanalyze Track**.
  * Reset Cue Points is unavailable until then.
* **No automation.** No bulk relink and no automatic repair.

## 6. Library audit events in Monitoring

Bulk-edit applies, relinks, "not a duplicate" decisions and their important refusals appear in
**Monitoring → Recent Events** (category `library`).

* **Contents.** Each event names:
  * the operator;
  * a unique action id;
  * the outcome (`completed`, `partial`, `no_change`, `nothing_applied`, `relinked`, `recorded`,
    `already_decided` or `refused`);
  * counts;
  * at most 20 Track ids per list, with the full count;
  * Library-relative paths.
* **Never recorded:** tokens, cookies or credentials.
* **Timing and failure.** Events are written only after the work commits. A failure to write one
  never fails or repeats the operation.
* **Retention.** This is the operational event log, pruned after about 30 days. It is best effort,
  not a permanent audit archive.

## 7. Documentation corrections

* **[r0109](r0109.md).** The validator and renderer run as the same service account, so a check that
  one could not write the other's delegated cgroup was not an isolation boundary. The corrected
  note describes the real confinement:
  * root-owned interfaces;
  * unit hardening;
  * the per-render FFmpeg sandbox in `production/services/confined_exec.py`.
* **[Hour Refill rollout packet](../roadmap/2_27_PHASE_D_ROLLOUT_PACKET.md).**
  * **History.** The completed r0120/r0121 releases, migrations 0093–0098 and their manual approvals
    are now recorded as history.
  * **Still required:** default Off, dry run, not armed, and separate KOGR and WRJE approvals.
  * **Installing a release never activates Hour Refill.** This release activates nothing.
* **README.** Current Library features, the iPortal/content apps and services, the five Hour Refill
  causes, and an accurate disaster-recovery status. Physical bare-metal recovery still needs its
  second qualifying restore.

## 8. Not in this release

* **Reconciliation and files:**
  * no automatic deletion, import, repair or garbage collection of media;
  * no bulk relink;
  * no reanalysis after a relink.
* **Duplicates:**
  * no duplicate resolution (keep/delete) from the review page;
  * `apply_duplicate_resolutions` keeps its known limitations.
* **Roadmap work deferred:** import from reconciliation, and asset expiration and maximum-air rules.
* **No Hour Refill activation.** No change to any station's Hour Refill policy, host arming or
  category configuration.
* **No daylight-saving-time fix.** The separate DST playout fix is not part of r0125.

## Deployment declaration

* **No changes to:** migrations or a migration companion, static assets, Python or APT dependencies,
  systemd units, nginx, or the protected runtime.
* **Restarts, in the protected updater's fixed order:**
  1. `isadoraair-gunicorn`;
  2. `isadoraair-active-message-worker`, which runs the changed Track registration, deletion and
     waveform code in-process.
* **Not restarted:** the engine, encoders, Monitoring, RBDS and the spoken-render worker. They run no
  changed Track write path, so audio is not interrupted.
* **Timers and commands:** the analyzer, dedication and ingest timers, and every command, load the
  new code on their next ordinary start.
* **Publication** does not authorize installation at KOGR or WRJE. See
  [r0125_installation.md](r0125_installation.md).
