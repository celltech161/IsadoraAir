# r0109 — Phase C spoken-content infrastructure (dormant)

Predecessor: **r0108** (`4703a8648e0e0e3c02620d46c7684e2c0a569a18`).
Protected runtime: **generation 12 → 13** (runtime version stays 11, manifest
protocol 5, wire protocols 3/4).
Accepted engineering baseline: `a3900756b25500f3f8126d1a484789b5ba82ae0f`
(Phase C1 + C2A + C2B), plus the release-preparation commits on
`release/r0109-phase-c-spoken-content`.

## Release notes

### New

- **Spoken-content domain** — a permanent home for station-produced spoken
  items (announcements, PSAs, news and similar): item identity, a strict
  lifecycle with an append-only event history, and per-type configuration.
- **Isolated renderer** — a separate `isadoraair-render` service turns a
  validated recording into a finished, loudness-normalized FLAC rendition,
  one render at a time, fully separate from upload validation.
- **Five code-backed processing recipes** — `cal_events`, `usd239min`,
  `news_item`, `3min_ctr` and `lcl_psa`, each with exact, recorded
  provenance (recipe version, parameters and the exact background beds used).
- **Safe library projection** — a delivered item becomes a normal library
  Track: *current edition* types keep one stable Track that each new delivery
  replaces in place; *accumulating* types get one Track per item. Files are
  published atomically and verified byte-for-byte.
- **Recall, expiry, detach and reconciliation** — withdrawn or expired content
  stops being playable at once; deleting a projected Track detaches it for
  good; a reconcile command repairs or reports drift (with a read-only
  dry-run).

### Operational

- **Two new services**, installed and started by the update:
  `isadoraair-render` and `isadoraair-spoken-render-worker`.
- **Protected-runtime generation 13** authorizes exactly those two units.
- **No spoken content type is enabled.** The new domain arrives empty and
  dormant: nothing is rendered, delivered or added to the library until an
  administrator configures and enables a type.
- After the update the operator completes the post-install checks below,
  including the **Runtime Recovery refresh** for generation 13.

### Safety

- Existing music, imaging, logs, voice tracking and playout behave as before
  (ordinary Tracks keep exactly their previous on-air eligibility).
- Spoken content remains dormant until configured.

### Compatibility

- The `.env` needs **no edit**; every new setting has a safe default
  (below).
- OGRemote is untouched. Active messages (Phase D), assignments/work queue
  (E), legacy import (F), cutover (G), legacy retirement (H) and occurrence
  voice tracking (2.6) are **not** included.

## What the update does

Planned by Update Center from r0108 (no manual operations, no migration
approval, no apt/pip/nginx changes, no collectstatic):

| Step | Action |
| --- | --- |
| 1 | Protected-runtime handoff to generation 13 (signed `primary-release` attestation, threshold 1) |
| 2 | **Host preflight** (read-only, as the application account, staged r0109 code) |
| 3 | Database checkpoint (`pg_dump`) |
| 4 | Guarded migrations, in order: `production.0002_referenceaudio`, `spoken.0001_initial` — both additive (new tables only) |
| 5 | Checkout fast-forward r0108 → r0109 |
| 6 | Units: install new `isadoraair-render.service` and `isadoraair-spoken-render-worker.service`; one `daemon-reload`; `enable --now` each (start on r0109 code). Each start job completes only through the unit's start gate (below); each is then verified `active` |
| 7 | Restart `isadoraair-gunicorn`, `isadoraair-engine` (deck-open authority changed), `isadoraair-monitoring` (render readiness) |
| 8 | Postflight: checkout identity, clean schema, Gunicorn HTTP health |

Not restarted: `isadoraair-encoders`, `isadoraair-rbds` (neither imports
anything r0109 changes) and `isadoraair-validation` (not in the protected
restart allowlist; its code and protocol are unchanged, and the shared
sandbox launcher stays backward compatible, so it keeps serving on its
current process until its next restart).

### Host preflight

Registered against `production.0002_referenceaudio` in the target's
`updatecenter_migration_preflight`
(`production/services/host_capability.py`), run before the checkpoint, any
migration, the checkout advance, any unit install or start:

- `production.0002.render_host_capability`: unified cgroup v2; `cpu`,
  `memory`, `pids` available; the per-run leaf interface files; systemd ≥ 254;
  and a functional **render-profile** self-test — the launcher's own render
  sandbox must refuse a write, a read outside the render roots and a socket,
  make `clone3` fail with `ENOSYS`, and still run the exact `ffmpeg` the render
  service will use.

Any failure stops the job `MIGRATION_PREFLIGHT_BLOCKED` with per-facility
evidence; the application, database, units and services are unchanged.
Limitation (as in r0107): the generation-13 handoff (step 1) precedes the
preflight, so on an unsupported host the station is left on generation 13 with
r0108 code — generation 13 differs from 12 only by the two policy entries, and
a retry after the host is fixed resumes through the runtime-already-
authoritative path.

The renderer never listens until its start-up cleanup and a confined
toolchain probe succeed; at most **one** render runs at a time
(`PRODUCTION_RENDER_MAX_ACTIVE` is fixed at 1). The worker claims validated
spoken items through their lease, asks the renderer, and delivers through the
projection service; with no spoken type enabled it finds no work (healthy).

### What "successful install" means

Update Center runs `systemctl enable --now` for each new unit and then checks
`ActiveState=active`. On its own that check passes the moment a `Type=simple`
process is forked — the r0109 station rehearsal showed a misconfigured
renderer reading `active/running` while it crash-looped. r0109 therefore gives
each new unit a **start gate** (`ExecStartPost=`), so the start job itself
completes only for a healthy service:

- `isadoraair-render`: `production_render_ready` waits (≤ 60 s) for the
  accepted readiness handshake (`production.services.render_health`: socket,
  status file, an answered empty request; the service binds only after its
  start-up cleanup and confined toolchain probe). Rehearsed: healthy start
  returns in ~1 s; an unstartable renderer fails the start job (`rc=1`).
- `isadoraair-spoken-render-worker`: the start job completes only if the
  worker survives 10 s of start-up (Django, database, start-up projection
  reconcile). Rehearsed: healthy start returns in 10 s; a worker that cannot
  reach the database fails the start job (`rc=1`).

So the update cannot report success while either new service is unstartable;
it fails visibly instead (see the rollback boundary). Projection readiness
needs no content: on a fresh install **zero spoken assets is the valid
state**. The post-install checklist still verifies the real system manager,
the delegated cgroup and a real render.

## Rollback boundary

- Update Center promises **no automatic rollback** (docs/UPDATE_CENTER.md,
  "Failure, retry, and rollback"). Before step 4 a failure leaves the
  application unchanged; between steps 4 and 5 the additive schema stays and
  r0108 code keeps running; after step 5 failures are
  `failed`/`manual_intervention_required` with evidence.
- **Schema is forward-only.** Both migrations only create tables; r0108 code
  runs correctly on the r0109 schema. Once spoken content has been delivered,
  rolling the application back is not supported (the r0108 engine knows
  nothing of projection authority); the checkpoint dump is the
  disaster-recovery reference for the pre-r0109 database, not a rollback tool.
- Protected runtime: generation 12 stays in the inactive A/B slot as
  last-known-good; the active generation never moves backwards.
- A start-gate failure at step 6 happens after the migrations and the
  checkout advance but before the step-7 restarts: the job is `failed` with
  the unit's evidence, the schema is r0109's (additive, safe for r0108 code),
  the checkout is r0109, and Gunicorn/engine/Monitoring keep their running
  processes until restarted. Fix the cause and retry, or fix forward.
- The two new units would stay installed under any manual application
  rollback; the r0108 checkout has neither command, so both would crash-loop
  harmlessly until r0109 is reinstated or they are disabled by hand.
- A defect found after installation is fixed forward with a corrected signed
  release — never by hand-editing production source, rows or files.

## Carried forward (not fixed in r0109)

Nonblocking C2B defects:
- `expire_due` can abort a worker pass on `projection_in_transition` until
  reconcile runs.
- After a category relocation, a lost Track link cannot be re-linked
  automatically (it fails closed with operator attention).

Accepted tradeoffs:
- Spoken-heavy preview cost is linear in spoken items; ordinary and realistic
  mixed queues are within the timing budget (ordinary items cost no query).
- Publishing a new edition makes the current-edition Track briefly
  unavailable (about 0.2 s for a 34 MiB file); a deck attempted in that
  window is skipped.
- A vanished witnessed Track fails closed (operator attention).
- No post-rename re-hash of the stable file (trusted service-account
  filesystem model; reconcile detects wrong bytes).

Deferred:
- Neither new service is in the protected restart allowlist; a later release
  that changes render or worker code needs a protected-runtime change to
  restart them through `services_requiring_restart` (or a controlled operator
  restart).
- The start gates are unit-level (`ExecStartPost=`); a `Type=notify`
  readiness signal from the services themselves would remove the polling.
  `isadoraair-validation` still has no start gate (unchanged from r0107).
- No dedicated persisted Monitoring check type for projection health (would
  need a migration); use `spoken_projection status` and the admin.
