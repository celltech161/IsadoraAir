# r0148: Aircheck capture source shown truthfully (roadmap 2.0-A)

r0148 contains one operator-visible correction (roadmap 2.0-A) and nothing else. Restart **Gunicorn only**. The audio
engine, encoders, Monitoring, RBDS and every other service keep running, and program audio is not interrupted.

| Change | Engineering commit | Review |
|---|---|---|
| 2.0-A — Aircheck `airtap` Admin and source-attribution correction | `be7bc128d24f63bf7d147828dad3b7a8ea73919e` (one commit on r0147; the accepted commit itself, not cherry-picked, squashed or rewritten) | Independent Codex review: ACCEPT — ready for release qualification; no P0, P1, P2 or other product defects |

The engineering commit changes four files: `aircheck/admin.py`, `aircheck/services/recorder.py`,
`aircheck/tests/test_source_attribution.py` (new) and `aircheck/models.py`, where the change is **documentation
only** (a docstring and a comment; the model definition, its fields and the schema are unchanged). There is no
migration, template, static, configuration, systemd, dependency or protected-runtime change.

## What changes for the operator

**The inherited problem.** Aircheck Configuration in Django Admin showed an editable **Source device** box. Nothing
acted on it. Aircheck does not open an audio device of its own: it records the program feed that the default
Liquidsoap encoder group already captures from `airtap` and shares with its encoders. Whatever was typed into the box
changed nothing about what was recorded, yet it was copied onto each new recording session, so a stale or wrong value
mislabelled new recordings.

**The correction.**

1. Aircheck Configuration no longer offers an ineffective editable source-device field.
2. **Capture source** is shown read-only as `airtap — shared default encoder-group source`, with the explanation that
   Aircheck records the same program feed used by the default Liquidsoap encoder group and that there is no
   independent capture device selection.
3. Aircheck continues to record the existing shared program feed. Recording routing, format, bitrate, output
   directory, filename template, cutting, locking, file handling, finalization and error behavior are unchanged.
4. **Newly created** Aircheck sessions use the authoritative `airtap` identifier, the same constant the default
   encoder group uses. A stale or arbitrary value in the legacy configuration column is ignored for new sessions.
5. **Historical and already-active sessions keep their original metadata.** Nothing is backfilled, normalized or
   reinterpreted, whether a session is active, completed or failed.
6. The legacy configuration column and its stored value are preserved. A normal Admin save (including a crafted
   request that contains a legacy source value) cannot modify it.
7. **No database migration is necessary.**

**What the display means.** The Capture source line establishes the source **identity**: which feed Aircheck records.
It is not a probe. It does not show that the encoder group is running, that the `airtap` device is available or that
audio is present, and it opens no device and contacts no encoder or Liquidsoap control socket. Encoder and Aircheck
health are shown where they were shown before.

## Testing and review

- Independent Codex review accepted the engineering commit and found no product defect.
- The new module `aircheck.tests.test_source_attribution` passes **17 of 17** in the guarded validation runner. It
  covers: the Admin page showing the canonical source read-only with its explanation and no editable control;
  `source_device` absent from the editable fields and from a forged POST; an unrelated valid save preserving the
  stored legacy value; no device enumeration or process spawn when the page renders or saves; a new session recording
  `airtap` while the legacy value is deliberately wrong, through both `start_recording` and the Start API (the only
  session-creation path); existing active, completed and failed labels unchanged through start, stop and
  finalization; one shared input and one recorder in the default encoder group only; no recorder or telnet in a
  nondefault group; and no change to a generated script, fingerprint or running child when the legacy value changes.
- Engineering regression run over `aircheck`, `encoders` and the runtime-requirements and fdkaac-tooling modules:
  690 tests run, 689 passed, 1 skipped, 0 failures, 0 errors, against 673 run on unmodified r0147 (672 passed, the
  same 1 skipped); the difference is exactly the 17 new tests. The one skip is the audited fdkaac archive integration
  test, which needs `ISADORAAIR_FDKAAC_SOURCE_DIR`. The r0058 HE-AAC capability gating, r0082 Aircheck containment and
  recovery, and the encoder reconciliation and last-known-good suites are inside that run.
- Negative controls: against unmodified r0147 nine of the new tests fail; reverting only the recorder change fails
  three, and reverting only the Admin change fails six.
- No physical Liquidsoap or ALSA experiment was run, and none is claimed. The topology tests inspect the generated
  script and use the isolated encoder-manager harness with a faked process launcher.
- The three separately tracked 1.22 test deficiencies are outside this release and are not touched.
- The release qualification evidence (contract, chain, trusted-planner parity and regression comparison with r0147)
  accompanies the release.

## Unchanged behavior

r0148 does not alter:

- the Liquidsoap encoder scripts, the default encoder group's input, desired or running encoder identity,
  last-known-good selection, reconciliation, configuration fingerprints or telnet commands;
- audio routing, ALSA configuration or the encoder topology;
- Aircheck format, bitrate, output directory or filename template, or applying a format change to the running
  recorder (format and bitrate are still baked into the encoder script and still need the encoder restart they needed
  before);
- Aircheck start, stop, working-buffer, segmentation, recovery and finalization behavior;
- existing Aircheck sessions and any value stored in the database;
- the playback engine, Remote DJ, Weather/AMBER alerts, Active Messages or station settings.

## What it is not

r0148 does **not** include any of the following; each remains open or planned under roadmap item 2.0 and later:

- a rolling archive or retrospective recording;
- a configurable working-buffer size;
- an archive capacity calculator;
- retention or storage management;
- runtime reconciliation of the Aircheck format or bitrate with the running encoder (format and bitrate changes still
  require the existing encoder restart);
- scheduled Aircheck or the Talent Skimmer;
- any audio-routing or encoder-topology change.

## Limitations (accepted; not remediated in r0148)

1. **Identity, not health.** The Capture source line reflects the source constant the encoder group is built from. It
   does not measure the running encoder, and it is not evidence of the encoder's current state at any station.
2. A station whose default encoder group is not running, or has no enabled default-group encoder, has no Aircheck
   recorder even though the page names the shared source; this release does not change that.
3. The legacy `AircheckConfig.source_device` column and its (now unused and undisplayed) help text remain in the
   database and the model so that no migration is needed. Removing them is a separate, later change.
4. Sessions created before this release keep whatever label they were given, including a value that was wrong at the
   time. They are not corrected retroactively.
5. The engineering evidence is isolated-harness evidence (faked process launcher, no real Liquidsoap or ALSA). No
   physical recording was started to prove the correction.

## Operational impact

There is no migration: `migrations_required` is empty and `migration_compatibility` is `null`. There are no new
packages, Python requirements, static assets, collectstatic, nginx changes, systemd units, manual bootstrap,
Aircheck configuration-data rewrite or protected-runtime changes: `protected_runtime` is `null`. Restart exactly:

1. `isadoraair-gunicorn`

Only Gunicorn loads the changed Admin and recorder code (`aircheck.admin`, `aircheck.services.recorder`). The Aircheck
buffer and recovery services run as oneshot units on timers and load the current code the next time they are
invoked; they need no restart and are not changed. The engine, encoders, Monitoring, RBDS and the persistent workers
load `aircheck.models` only, which changed in documentation alone. Under a direct r0147 → r0148 update **the audio
engine and encoders remain running** and program audio is not interrupted. A station on an earlier release still
receives every intervening migration and restart in its cumulative plan.

Publication does not authorize installation: each station requires separate preflight, installation authorization and
operational acceptance; see `r0148_installation.md`.
