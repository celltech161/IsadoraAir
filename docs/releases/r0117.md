## Release notes

### Console (2.23 Phase 1/1B, accepted earlier)
- **Waveform and deck cards.** The 62 px waveform has a white playhead with triangles, and deck cards
  are compact.
- **Microphone controls.** Microphone icon chips, a disabled Line In placeholder, and an honest Eject
  label.
- **Engine-truth status.** Command feedback reflects engine truth, and engine snapshots are ordered by
  revision.
- **Remote DJ.** The Remote DJ owner/observer identity is shown, and the Remote Mic control is only
  enabled for the verified owning browser.

### Start Next (new)
- **The control.** A conspicuous **Start Next** control sits between the decks: a middle column on
  desktop and tablet, its own row between stacked decks on mobile. On `/remote-dj/` mobile it sits
  between the live deck and the compact preview.
  - It is shown only to holders of the new capability **`playout.start_next`**.
  - That capability is granted to Station Administrator and Remote Host.
  - It does **not** imply Eject, Pause, Seek or Studio Mic.
- **Engine-owned transition.**
  - The playing deck is faded on its own mixer input (an equal-power curve via GstController) over the
    configured time.
  - The next item starts from media position zero, timed so its cue-in lands at the end of the fade.
  - Exactly one queue occurrence is consumed.
  - During an existing crossfade only the older deck is faded and nothing new starts.
- **Nothing queued.** If nothing is eligible, it fades to silence ("completed to silence"); nothing is
  invented or consumed, and the end-of-queue authority (live fill, next hour) resumes as usual.
- **Request binding (mandatory).**
  - Every request is bound to the operator's press (`client_request_id`; an HTTP retry is the same
    engine request), to the engine run they saw, and to the exact live occurrences and generations
    they saw (`[]` when stopped).
  - The server and the engine both refuse anything missing or malformed.
  - The Console offers Start Next only when its status snapshot carries all of it.
- **Refusals.** Start Next is refused:
  - while a Voice Track transition, a seek, or a post-cancel restoration of the playing deck is in
    progress;
  - when stale (over 5 s), or from before an engine restart;
  - when duplicated, or when the decks or their generations changed since the click.
- **Fade lifetime.** Each live deck pad has at most one volume controller, reused for every fade,
  cancellation and restoration and released only with the pad. It is never removed or replaced while
  the mixer is running.
- **What the operator sees.** HTTP 202 shows only "Queued". Fading, completion, refusal, cancellation
  and failure are shown from the engine's own published status.
- **Settings.** Config → Playout Transport Config:
  - fade 2000 ms (250–10000 ms);
  - "Start Next switches Manual to Auto", default Off. It releases only an operator-owned Manual, never
    a microphone-held one or one held during Remote DJ reconnect grace.
  - Saved values apply to the next press; no restart is needed.

### Safety corrections
- **Eject during a crossfade.** Ejecting the outgoing deck no longer starts a third item.
- **Delayed Eject.** A delayed Eject of an empty slot is ignored. Eject now carries the occurrence it
  was pressed for, and the engine ignores it if that deck has moved on.
- **Eject and VT.** Eject of the VT outgoing deck completes the approved VT transition instead of
  stranding it ducked.
- **Natural VT transitions (an r0116 defect).**
  - A natural VT transition no longer lets the engine's empty-console teardown restart start a song
    under the outro VT, followed by a second song from the VT timer.
  - A stuck-deck watchdog retirement of the VT outgoing deck no longer strands VT.
- **VT timer identity.** VT timers and fires are bound to their sequence, so a play-now reload aborts a
  VT cleanly and can never fire a stale intro or start an extra item.

## Restarts, files, packages

- **Restarts:** `isadoraair-gunicorn` (views, templates, models, capability vocabulary) and
  `isadoraair-engine` (engine). The engine restart is a brief on-air interruption with the existing
  auto-resume, and ends any Remote DJ session.
- **Unchanged:**
  - no collectstatic (no static assets changed);
  - no systemd unit, package, requirements or nginx change;
  - no manual bootstrap.
- **GStreamer:** the fade uses `GstController-1.0`. Its typelib ships in `gir1.2-gstreamer-1.0`, the
  package that already provides `Gst-1.0`, so nothing new is installed. If it were missing, the engine
  would refuse Start Next with `fade_unsupported` and nothing else would change.
