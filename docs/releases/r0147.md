# r0147: First-audio stall recovery for ordinary unattended starts (roadmap 1.21-B1)

r0147 contains one broadcast-continuity change (roadmap 1.21-B1) and nothing else. Restart **the audio engine only**.
The engine restart interrupts program audio briefly and is subject to the r0144 engine restart safeguard.

| Change | Engineering commits | Review |
|---|---|---|
| 1.21-B1 — First-real-audio stall recovery | 9 commits on r0146, `28c98b3` … `5dbbfa5` (the accepted commits themselves; not cherry-picked, squashed or rewritten) | Independent Codex review: ACCEPT — ready for release qualification; findings B1-R1, B1-R2 and B1-R3 resolved |

Only `library/services/engine.py` and three existing test modules changed. There is no model, migration, template,
static, configuration, systemd, dependency or protected-runtime change.

## What changes for the operator

**The inherited gap.** When the engine claimed an ordinary scheduled item and opened a deck for it but the deck then
produced no real audio (a stalled decoder or source), nothing noticed: the item had been claimed, no real audio ever
arrived, and playout could sit silent until something else intervened.

**The correction.** When an ordinary **unattended** start produces no real audio within **1.0 second** of its deck
opening, the engine now:

1. retires that generation and **reopens the same scheduled occurrence once** (the original claim identity and
   timestamp are kept; it is the same unaired occurrence, not a new one);
2. if the retry also produces no real audio within 1.0 second, records **one critical engine event** ("No audio from
   '<title>'; occurrence skipped") and **advances playout** to the next item instead of staying stranded.

A warning event ("Deck N produced no audio; retrying '<title>' once") is recorded when the retry is queued. The
retry waits behind forced items, urgent items and the Weather/AMBER alerts already pending, so recovery never displaces
an emergency alert or an operator-forced item. A source that is merely slow but delivers real audio inside the
one-second window is **not** retried. When the first-real-audio signal and the deadline race, exactly one of them wins:
the item is never both aired and retried.

**Playback accounting is preserved.** A Play event is still recorded only when real audio is first delivered, so a
stalled attempt that never airs records none, and a retry that airs records exactly one. Generation fencing keeps a
late first buffer from a retired attempt from airing or being counted, and the retired deck's teardown is bounded.

**Retry identity lasts for the engine process.** An occurrence whose one retry allowance has been consumed stays
suppressed from automatic re-entry **for the lifetime of the engine process**. Reloading a log, replacing,
rescheduling, retiring or reactivating it does not restore the allowance. Only an engine restart resets it. The memory
cost is two integers per occurrence that actually consumed a retry (failures), never per item played.

## What it is not

- **It is first-audio startup recovery, not a generalized silence detector.** It acts only on a start that never
  delivers its first real audio. Silence or a stall *after* real audio has begun, decoder starvation mid-song and any
  other dead-air condition are not covered. r0147 does not eliminate dead air.
- **Operator-controlled starts and other excluded playback modes keep their existing behaviour:** Start Next, Eject,
  Manual mode, urgent and Weather/AMBER items, dedication intros, active messages, other operator or engine
  insertions, seek / resume / continuation generations and Voice Track admissions get no deadline and no retry. Only
  scheduled, fill, live-fill, installed-refill and DST-replay occurrences opened by the unattended engine are eligible.
- It adds no station configuration, no setting and no operator control. The 1.0-second deadline is fixed.

## Testing and review

- Independent Codex review accepted the final implementation (`5dbbfa5`). The three primary test modules pass 140 of
  140 (`test_engine_deck_lifecycle`, `test_engine_playback_accounting_semantics`,
  `test_engine_playback_boundary_evidence`) and the claim-contention compatibility suite 13 of 13.
- Real-GStreamer scenarios: a stalled start recovers on the retry (about 1.07 s); a retry that also stalls ends with one
  critical event and the successor airing (about 2.1 s); a source that delivers its first audio at 0.6 s airs without a
  retry; a contended start recovers; a reactivated retired log does not regain a consumed retry. Negative controls on
  unmodified r0146 fail behaviourally, and every mutant of the recovery logic was killed.
- Engineering validation had 47 inherited Active Messages `MediaRejected` fixture errors in the engineering runner,
  identical on unmodified r0146. They give no integration coverage for Active Messages; that exclusion is covered by a
  deterministic eligibility test.
- The release qualification evidence (contract, chain, trusted-planner parity and regression comparison with r0146)
  accompanies the release candidate.

## GStreamer preflight

r0147 does **not** change the deck mixer, deck bus or pipeline construction (the r0146 changes), and does not install or
upgrade any package. The r0146 Gate A / Gate B installation preflight therefore does **not** have to be repeated for a
station already running accepted r0146. A station that is not on r0146 receives r0146 in its cumulative plan, and the
r0146 preflight (`r0146_installation.md`) remains mandatory for it. `r0147_installation.md` states the exact
condition.

## Limitations (accepted; not remediated in r0147)

1. **Only first real audio is watched.** A start that delivers some audio and then stalls, mid-song decoder starvation
   and silence from a healthy source are not detected or recovered.
2. **Roadmap 1.21-C (durable crash / power-outage checkpoint recovery)** remains open.
3. **Roadmap 1.21-D (live-fill and exhausted-hour scheduling) and 1.21-E (Monitoring continuity classification and
   automatic dead-air recovery)** remain open; the new critical and warning events are ordinary engine events and add
   no new Monitoring classification.
4. **One retry only.** A second failure skips the occurrence; it is not queued for a later attempt, and the skipped
   occurrence stays suppressed until the engine process restarts.
5. **A skipped occurrence is not replayed.** After the critical event the engine advances to the next item; r0147
   adds no make-up scheduling for the skipped one.
6. **Operator-started and excluded playback modes are unprotected** by this feature (see above).
7. The 1.0-second deadline is fixed and based on measured KOGR starts (prepared to Play event: median about 0.04 s,
   99.9th percentile about 0.11 s). A station with unusually slow media start-up could see a retry that was not needed;
   it would be visible as a warning event, and the occurrence still airs and is counted once.
8. The Aircheck `airtap` Admin and session-attribution correction is a separate change and is not in r0147.
9. Everything r0146 left open (decoder starvation, the 16-bit deck bus, dithering, the GStreamer version, Hour Refill
   policy) is unchanged; r0147 does not upgrade GStreamer.

## Operational impact

There is no migration: `migrations_required` is empty, `migration_compatibility` is `null` and no manual migration
authorization exists. There are no new packages, Python requirements, static assets, collectstatic, nginx changes,
systemd units, manual bootstrap or station configuration changes, and `protected_runtime` is `null`. Restart exactly:

1. `isadoraair-engine`

The only changed production module is the engine's; its changed code lives in the playback engine and runs only inside
the engine service, so Gunicorn, Monitoring, the encoders, RBDS and the workers keep running. The engine restart
**interrupts program audio** briefly; install in an approved maintenance window. A station on r0144 or later installs
from an Update Center with the **engine restart safeguard**, which refuses the installation while a studio microphone or
Remote DJ is live or engine status is unknown. Do not override it to install. A station on an earlier release still
receives every intervening migration and restart in its cumulative plan.

Publication does not authorize installation: each station requires separate preflight, installation authorization and
operational acceptance; see `r0147_installation.md`.
