## Release notes

### Fixed

- **Static files after an update.** Update Center runs `collectstatic` under
  the updater's `UMask=0077`; a static directory that did not exist yet was
  created `0700` and nginx answered 403 (r0107's iPortal scripts — fixed by
  hand on KOGR — and `weather/css`/`weather/js` before them). New static
  directories and files are now created `0755`/`0644` on their descriptors,
  and every run repairs existing too-restrictive static entries.
- **Static destination confinement.** Every `collectstatic` destination
  operation — locating/creating `STATIC_ROOT`, directories, existence and
  time checks, writes, replacement, deletion, permission repair — works
  through directory descriptors anchored at `/` with no-follow opens. A
  symlink or a substituted directory anywhere on the destination path (the
  checkout, `STATIC_ROOT`, an asset directory, an asset) can no longer steer a
  write, delete or chmod outside `STATIC_ROOT`; a non-regular entry where an
  asset belongs (directory, FIFO, socket, symlink) is replaced, never skipped
  as "unmodified" (a non-empty directory fails the run loudly).
- **Voice-track preview after a re-record.** The Track and Voice Tracks pages
  preview `?take=<current take>`, so the browser never replays the previous
  take; an older page's link redirects (after the access check) to the
  current take. Engine/on-air resolution is unchanged.
- **Validation service in Monitoring.** A *Systemd Service* check of
  `isadoraair-validation.service` also checks the service's socket, its
  status file and an empty-request handshake (no validation load): running,
  restarting/restart loop, not listening, unresponsive, bad status. The card
  shows the effective limits and has no Restart button. Monitoring stays
  read-only. **Requires the post-install step above.**
- **iPortal.** Punch-in now reads "keep the rest of the take after it" /
  "discard the rest (the take ends where the new recording ends)" (both always
  record over the take from the playhead); reopening a workspace with a take
  already on air says so and offers **Edit the on-air take** — opening still
  changes nothing.

### Intentional constraints

- **`STATIC_ROOT` must be a symlink-free physical path.** Settings derive it
  from the resolved checkout (`BASE_DIR`), so the `/opt/isadoraair` symlink is
  fine: on KOGR it is `/home/jreed/isadoraair-django/staticfiles`. A symlinked
  `STATIC_ROOT` (or `staticfiles` entry) makes `collectstatic` refuse.
- **`collectstatic --link` is unsupported** (refused). Update Center and DR
  restore both use plain `collectstatic --noinput --skip-checks`.
- A planted symlink *directory* inside `STATIC_ROOT` stops a plain run until it
  is removed (`collectstatic --clear` removes it as an entry, never following it).

### No operational changes

- No migrations. No new or changed units. No package, requirements or nginx
  change. Protected runtime stays generation 12.
- Not restarted: `isadoraair-engine`, `isadoraair-validation`,
  `isadoraair-encoders`, `isadoraair-rbds` — none imports anything r0108
  changes in a way they use (the engine's `VoiceTrack` gains two preview-only
  properties; the validation service's code is unchanged).

## Runtime Recovery

r0108 does **not** require a new Runtime Recovery payload. The backup's
freshness check (`isadoraair/recovery_freshness.py`) binds the payload to the
protected-runtime **descriptor** committed in the checkout (generation and
SHA-256), not to the application SHA; r0108's descriptor and policy are
byte-identical to r0107's. The current payload
`phase-d-runtime-recovery-20261008T033337Z` (generation 12, descriptor
`7dbe7e31…`) evaluates `current` against the r0108 tree.

## Rollback boundary

Update Center promises no automatic rollback. r0108 has no schema change; a
manual return to r0107 code is supported (r0107 storage would again create new
static directories `0700` — repair by hand as at r0107 acceptance). The
validation Monitor Check row is plain data: r0107 Monitoring would treat it as
an ordinary systemd check.
