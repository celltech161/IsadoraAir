# r0134: Weather speech on calibrated FLAC; Dedication peak limiter

r0134 changes how generated Weather speech is encoded and how loud it is, and adds a peak safeguard to Dedication
intros. It adds no setting, migration, package or service, and it changes nothing about the playout engine, Web
Requests scheduling, library import, the shared text-to-speech runtime, KanDrive, Hour Refill or the protected updater.
It is an encoder-and-filename transition, not a media migration.

## What changes for the operator

### Weather speech is now FLAC, at the station's level

All four Weather products (temperature, observations, forecast, alert) are now produced as 44.1 kHz stereo 16-bit
FLAC instead of 320 kbps MP3. The generated speech used to air about 6 LU quieter than the station's -16 LUFS reference.
Each product now gets a fixed, calibrated gain and a peak limiter before encoding. The existing one-second silence at
the start of every file is unchanged.

| Voice | Product | Gain |
|---|---|---|
| Max Weatherly | Forecast, Observations, Alert | +6.0 dB |
| Max Weatherly | Temperature | +4.75 dB |
| Claira Sky | Forecast, Observations | +6.5 dB |
| Claira Sky | Temperature | +4.75 dB |
| Claira Sky | Alert | +6.5 dB (**provisional**) |

Measured results on the station's existing audio: about -16 LUFS integrated with a true peak near -1.5 dBTP. The peak
limiter is `alimiter` at a 0.84 linear ceiling (about -1.5 dBFS), with no automatic make-up gain and no time shift.
The gain is one fixed value per voice and product: no per-clip measurement and no loudnorm. A voice that has no
calibrated row uses Max's values and logs a warning instead of failing the broadcast.

### Permanent filenames

The files keep the same name on every generation. NWS and AMBER-family alerts both publish to the same alert file.

| Category | New filename |
|---|---|
| WxTemp | `current_temp.flac` |
| WxObs | `current_obs.flac` |
| WxForecast | `forecast.flac` |
| WxAlert | `wx_alert.flac` |

### Metadata

FLAC carries its tags as Vorbis Comments rather than ID3. The artist and title values are the same ones the MP3 files
carried, and the library's tag reader populates the Track from them (covered by a test that encodes a real FLAC).

### New Tracks, old Tracks

- A new FLAC is registered like any other library file, by its own path. **It receives an ordinary new Track ID.** No
  historical Track ID, playlist item, rotation slot, approved log or play event is migrated or rewritten.
- Regenerating the same FLAC updates the same FLAC Track.
- **Existing MP3 files and Tracks are not deleted, deactivated, re-pointed or rewritten by this release or by any
  FLAC publication.** MP3 candidates are still accepted by the publisher.
- The old MP3 Track and the new FLAC Track therefore coexist in the same category until the operator retires the MP3.
  That is a real condition with consequences, not a harmless state; see below.

### Dedication intros

Dedication intros get a peak limiter only: ceiling 0.84, **0.0 dB gain**, native mono FLAC, no resampling, and no time
shift, so the duration and cue markers are unchanged. A native mono intro already plays at about -16 LUFS once the
pipeline duplicates it into both channels. On the 28 intros present at calibration, 9 had exceeded -1 dBTP and every
one is at or below -1.3 dBTP with at most 0.1 LU of loudness change. The limiter is an opt-in setting used only by
Dedications; every other announcement is produced exactly as before.

### KanDrive

KanDrive's two-pass EBU R128 loudness normalization is unchanged.

### Diagnostics

Weather Setup Status and the Weather monitoring probe now expect the four `.flac` files. A leftover MP3 does not count
as evidence that the FLAC workflow is healthy. Alert applicability, freshness and provenance rules are unchanged: the
alert is event-driven, so with no active alert the FLAC legitimately does not exist yet.

## What the operator must do (nothing is automatic)

The operator manages playlists, rotations and the legacy MP3 Tracks. Installing r0134 does none of this.

- **Playlists, rotations and approved logs** that reference the Weather MP3 Tracks keep referencing them. Nothing
  regenerates those MP3 files any more, so they will air stale unless the references are moved to the FLAC Tracks and the
  MP3 Tracks are retired from future selection. Leaving both eligible risks duplicate scheduling.
- **WxAlert is special.** The engine's urgent insert takes the first ready Track in the `WxAlert` category with no
  ordering, and this release does not change that. While the old `wx_alert.mp3` Track stays eligible, an alert can
  select it instead of the new FLAC. Make the old MP3 ineligible for urgent selection as part of the cutover.
- **The alert FLAC does not exist until a real qualifying NWS or AMBER-family alert occurs.** Until then, with the old
  MP3 retired, the category has no ready alert Track, and there is no automatic fallback to the MP3. See the runbook.
- **Deleting the old MP3 files** is a separate, later decision after acceptance.

## Known limitations and open acceptance

- **Claira's alert gain (+6.5 dB) is provisional.** No alert has aired in Claira's hours since calibration began, so
  it reuses her forecast and observation value. Replace it after a real Claira alert has been measured.
- Claira's output was measured but not auditioned. **Operator listening acceptance of the calibrated audio is still
  outstanding;** only Max's samples were auditioned.
- A very hot or heavily saturated source can still reach about -0.5 dBTP after limiting. Real speech measured at or
  below -1.3 dBTP.
- `WeatherConfig.alert_sound_trigger_events` (`weather/models.py`) has stale help text that still names
  `wx_alert.mp3`. Changing it would need a migration, so it is a separate cosmetic follow-up.
- The broader test suite carries failures that already exist on r0133 in unrelated areas (see the evidence); this
  release's own areas are green.

## Deployment declaration

There are no migrations, migration companion, packages, Python requirements, collectstatic, nginx, systemd units or
protected-runtime changes. `protected_runtime` is `null`, so no protected descriptor, policy generation, offline
release signature or attestation is created.

Restarts, in canonical order: `isadoraair-gunicorn`, then `isadoraair-monitoring`. Gunicorn serves Weather Setup
Status, which uses the changed diagnostics. Monitoring is a long-lived process whose Weather probe imports the same
diagnostics, so it needs the new code. The Weather producers, the publish command and the Dedication intro generator
are fresh processes started by their timers and pick up the new source on their next invocation; they need no restart.
The playout engine is **not** restarted: it imports `webrequests.services`, but only for scheduling and song-request
functions, and the changed lines are in the dedication-synthesis function that only the separate
`generate_dedication_intros` command calls. The encoders, RBDS, Active Messages and spoken rendering are not restarted
either. KOGR and WRJE each need separate installation authorization; see `r0134_installation.md`.
