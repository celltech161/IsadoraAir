# r0123: protected cue markers, trusted waveforms and Monitoring polish

r0123 completes roadmap 1.21's cue-marker and waveform-integrity work and roadmap 2.24's
Monitoring dashboard refinement. It does not change playout decisions, alarm policy, audio
dependencies or the protected updater.

## Cue markers and waveform trust

- All eight Track cue markers now have one authoritative mutation service, optimistic revision
  control and individual Lock, Unlock and Approve actions.
- Historical values whose provenance is unknown remain protected. Operator approvals and retired
  approvals are durable and append-only, including previous-audio review state.
- Repick and Reset preserve protected values. A calculation that started from stale marker state
  is discarded rather than overwriting a newer operator decision.
- Version-2 waveform caches bind to a decoded-audio identity. A legacy or mismatched cache may
  still be displayed, but Repick does not trust it until an operator refreshes that Track.
- **Refresh Waveform Only** regenerates one cache without changing source audio or Track metadata.
  Long-form refresh runs in one bounded background process with exact per-request status, one
  station-wide slot, time limits and a memory budget.
- Waveform publication is atomic and transaction-fenced across analysis, announcements, weather
  and active-message ingestion.
- Category relocation retains the original media through database commit, never overwrites a
  destination, and uses descriptor-relative no-follow operations. Category codes must be one safe
  path component. Symlinked source or destination layouts fail closed; direct child mount points
  remain supported, including the exclusive cross-filesystem copy path.

Existing waveform caches are not regenerated during installation. The 165 waveforms repaired on
October 29 and the seven retained orphan files are not touched by this release.

## Monitoring dashboard

- Cards are denser and easier to scan on desktop and mobile.
- Redundant elapsed-state lines are removed.
- Long service names and transmitter measurements wrap cleanly.
- Monitoring checks, thresholds, alert routing and backend behavior are unchanged.

## Migration and deployment

`library.0099_track_cue_marker_authority` adds:

- `cue_marker_state` (JSON, database default `{}`);
- `cue_marker_revision` (bigint, database default `0`); and
- nullable, indexed `analysis_requested_at`.

It has no data migration. Existing marker columns, Ready-to-Air values and Track relationships are
unchanged, and no historical provenance is invented. The Update Center classifies the first two
`AddField` operations as manual because their non-null fields use database defaults. The immutable
r0123 companion authorizes exactly those two operations.

The release requires no collectstatic, package, systemd-unit, nginx, dependency or protected-runtime
action. The Update Center restarts Gunicorn and the active-message worker, in that order. Analyzer,
weather and generated-content one-shot jobs load the new code on their next invocation. The engine
and Monitoring service do not require restart.

## Filesystem prerequisites

The application user must retain read access to source media and write access to `WAVEFORMS_DIR`,
including permission to create `WAVEFORMS_DIR/.locks`, lock files and same-directory temporary cache
files. FFmpeg and FFprobe remain the existing installed binaries; no new media package is required.
Do not replace a category directory with a symlink: r0123 intentionally refuses that layout.

## Qualification scope

The four packages and six corrections received independent focused review. Migration preservation,
manual-operation identity, manifest/companion trust, Update Center planning and focused r0123
regressions are release gates. The established sandbox cannot run browser/Playwright or VM/systemd
field checks, and media-validator suites retain their documented sandbox limitations; those are not
represented as passing. Station field acceptance follows a separately authorized installation.
