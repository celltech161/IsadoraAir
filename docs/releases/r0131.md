# r0131: DST fall-back continuity and safer song import

r0131 fixes the November 1, 2026 fall-back outage and hardens the existing one-shot
`import_songs` command. It does not add a scheduling framework, change normal-day
playout, or run an import automatically.

## Fall-back continuity

During a fall-back transition, IsadoraAir may load and play part of the next approved
hour during the first occurrence of the repeated wall-clock hour. Previously, when the
clock reached that approved hour for real, the already-played rows were exhausted and
the station could remain silent for the hour.

r0131 detects only the actual whole-hour fall-back successor in the station timezone.
At that boundary it creates one durable replay authorization for the approved log and
copies only eligible ordinary occurrences that genuinely reached their first audio buffer
before the real hour. The replay rows retain their source identity and are
counted as separate airings only when they themselves reach a first real buffer.

The replay deliberately excludes requests, one-shot and late inserts, prior replays,
and other nonordinary source classifications. The authorization marker and replay rows
commit in one transaction under the approved log's row lock. A normal engine restart
therefore cannot authorize a second replay pass, and a failed transaction authorizes
nothing. Outside the bounded fall-back window, ordinary rollover, early rollover,
queue exhaustion, crossfade and normal-day behavior are unchanged.

`library.0100_dst_fallback_replay_pass` adds one nullable, noneditable
`PlaylistLog.dst_replay_hour_start` field and extends the existing `LogItem.origin`
choices with `dst_replay`. It has no data migration and no manual operation. Existing
rows remain unchanged with a NULL authorization marker, and r0130 writers remain
compatible while the additive migration is present.

## `import_songs` hardening

`import_songs` now:

- ignores AppleDouble `._*` files and `__MACOSX` trees;
- confirms candidate audio can actually be decoded before any Track write;
- treats missing, replaced or malformed files as skipped inputs;
- preserves an existing Track when a replacement fails validation; and
- applies the same eligibility decision in `--dry-run` mode.

Category override, folder inference and valid tagged or tagless imports retain their
established behavior. Validation is intentionally one file at a time: this remains a
manual maintenance command, not a background importer or playout path.

## Deployment declaration

The release requires the single additive migration above. It needs no trusted migration
companion, package, dependency, collectstatic, nginx, systemd-unit or protected-runtime
change. The trusted updater restarts Gunicorn and then the engine. Encoders, Monitoring,
RBDS, Active Messages and spoken rendering are not declared for restart.

The fall-back behavior is covered by deterministic timezone, timeline, restart,
concurrency, rollback, source-eligibility and first-buffer accounting regressions. A
real fall-back cannot be field-tested at release time; station installation must instead
verify the exact release identity, migration, trusted action plan and normal playout.
KOGR and WRJE each require separate installation authorization.
