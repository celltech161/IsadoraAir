# r0139: Console UI and navigation refinements

r0139 refines the Console, Remote DJ, UI Theme administration and shared navigation. It is presentation-only apart
from one additive migration that stores two new display preferences. Playout, scheduling, engine queue handling,
playback authority, Remote DJ authorization and the meaning of existing queue controls are unchanged, and the
defaults reproduce the r0138 appearance.

## Station-wide display settings

Django Admin → UI Theme → **Console / Remote DJ — Log Display** now has, in order:

1. **Show played items** (unchanged from r0138; defaults Off);
2. **Played item darkening** (`UITheme.played_item_darkening`): a 0–100% slider, default 55%, with the selected
   percentage beside it. It is the opacity of a black overlay over each played row's own category color. At 55% the
   page looks exactly as in r0138; at 0% a played row keeps its category color; at 100% it is black; in between the
   category hue stays visible under proportional shading. Category colors are not modified;
3. **Current item outline color** (`UITheme.current_item_outline_color`): the existing color picker and opacity
   slider, default opaque white, applied to the thin outline of the row(s) the engine reports as actually playing.
   The outline's geometry is unchanged, and a claimed, preloaded or paused deck is still not outlined. During a genuine
   crossfade both playing rows may be outlined.

Both settings are station-wide, apply to the Console and Remote DJ and take effect when the page is reloaded.

Under **Deck Transport Buttons**, the existing `deck_transport_disabled_opacity` field now uses the same reusable
opacity slider ("0% = invisible, 100% = fully opaque") instead of a numeric box. The field, its default (30%) and its
0.0–1.0 stored values are unchanged, an existing configured value is preserved even when it is not a whole percent,
and the CSS for disabled deck buttons is unchanged. No migration is involved in that change.

## Coming Up table

- **Play indicator.** With Show played items On, a row the engine identifies as actually playing shows the deck
  transport's existing Play glyph in the leftmost column, labeled "Currently playing". It is decorative: not a button,
  not draggable and not a transport control. Claimed, queued, paused or preloaded rows and ordinary history rows do not
  show it; both rows show it during a genuine crossfade.
- **Drag-sort indicator.** The `☰` glyph is replaced by an inline SVG of two solid, rounded triangles (up and down)
  that inherits the cell's color. The same `qt-drag-handle` element and pointer handling remain, so reorder payloads,
  drop targets and queue authority are unchanged, and only upcoming rows have the handle.
- **NEXT button.** The upcoming-row Next action is a compact dark translucent pill with green **NEXT** lettering and an
  SVG double-chevron badge. It is the same button, handler, eligibility and authorization as before.
- **Header alignment.** Headers now align with their cells: the drag/play column is centered, `#` is right-aligned,
  Artist, Title and Cat are left-aligned and Dur, Intro and Time On are right-aligned. The cause was CSS specificity:
  the table-wide left alignment had overridden the earlier per-column header rules. Column order, sticky headers, row
  colors and responsive horizontal scrolling are unchanged.

## Shared navigation clock

The station clock in the navigation bar is now a keyboard-accessible button that opens and closes the same menu as
the hamburger button. Either control can open or close it, and both always report the same `aria-expanded` state.
The clock keeps its station-timezone formatting and one-second refresh. On narrow phones a small rule keeps both the
clock and the hamburger on screen. The change is in the shared base template, so it applies to every page; menu
destinations, permissions, grouping and logout are unchanged.

## Color-widget contract

The shared admin color widget (`RGBAColorWidget`, used by UI Theme, Category Kind and FX Cart colors) and the
new `library.models.validate_css_color` validator now agree:

- supported hexadecimal colors have exactly 3, 4, 6 or 8 digits (`#fff`, `#fff8`, `#FFFFFF`, `#FFFFFF80`);
  hexadecimal alpha is interpreted correctly, so `#FFFFFF80` is white at about 50% opacity;
- `rgb()` and `rgba()` are supported, with channels restricted to 0–255 and alpha to 0–1; five- and seven-digit hex,
  out-of-range channels and alpha, and malformed functions are rejected;
- opening an admin form does not rewrite an untouched color, so shorthand and alpha-hex values survive unrelated
  saves; an unreadable legacy value is left exactly as stored;
- an intentional picker or opacity change recomputes a valid `rgba()` value;
- Category Kind and FX Cart colors keep their existing behavior.

The unpublished migration 0102 references the same importable validator as the model.

## What remains unchanged

- The engine, its queue, ETAs, deck transitions, playback accounting, log building and scheduling.
- The read-only log-history endpoint and the Show played items merge, including bounded fetching.
- Remote DJ authorization, GroupAccess, queue authority and server-side reorder behavior.
- Voice Tracks, Web Requests, Hour Refill, Active Messages, Weather/AMBER and encoders.
- There are no new packages, Python requirements, static assets, nginx changes, systemd units or protected-runtime
  changes. `protected_runtime` is `null`, collectstatic is not required, and `library/services/engine.py` is not
  changed from r0138.

## Known limitations

- **NEXT pill contrast.** The pill's background is translucent, so unusual custom category palettes (very light or
  very saturated rows) can reduce the contrast of its green lettering. This has not been addressed in r0139.
- The following behaviors are inherited from r0138 and are not introduced or corrected here: the server-side reorder
  API may accept played `LogItem` IDs from an otherwise authorized direct caller (the browser sends only upcoming IDs);
  default Remote DJ GroupAccess and the `schedule.edit` requirement may prevent Remote DJ reorder even though the
  table shows its control; an item can become claimed during a drag already in progress; and narrow screens may still
  need horizontal scrolling for the queue table.

## Engineering qualification

The accepted engineering review recorded 117 guarded targeted application tests passing at the final engineering
commit; 42 of 42 Console/UI scenarios in Chromium and in Firefox against the real rendered pages; 10 of 10 real
widget-JavaScript scenarios; failures of the intended negative controls against the previous implementation; migration
0102 as two additive operations; and clean Django system and migration-drift checks.

The committed Django Playwright module could not launch installed browsers inside the guarded bubblewrap environment
(executable-availability errors, not assertion failures). The host-driven browser harness exercised the real rendered
pages and JavaScript, but it is separate and is not represented as an execution of that committed module. A broader
exploratory historical-migration aggregation reported failures in stale expected migration lists and older
Monitoring/Weather classifications; they are inherited and do not affect the r0139 migration contract, which the
r0139 release-contract tests assert directly.

## Deployment declaration

Apply the additive migration `library.0102_uitheme_log_display_appearance` (two non-null `AddField` operations with
literal defaults, `played_item_darkening=0.55` and `current_item_outline_color="rgba(255, 255, 255, 1.00)"`; existing
`UITheme` rows receive those defaults), then restart exactly:

1. `isadoraair-gunicorn`

No manual migration-authorization companion is required. The engine is **not** restarted: r0139 does not change
engine source or playout logic, so installing it does not interrupt program audio or a Remote DJ session.

Publication does not authorize installation at KOGR or WRJE. Each station requires separate preflight, installation
authorization and operational acceptance; see `r0139_installation.md`.
