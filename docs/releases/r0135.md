# r0135: Playout continuity after the KOGR 2026-11-11 dead-air incident

r0135 corrects two playout-engine failures that together produced about three minutes of dead air on KOGR at the end of
the 21:00 hour on Wednesday 2026-11-11, followed by overlapping starts at the 22:00 rollover. It also includes the
corrections from two independent reviews of that fix. It adds no setting, migration, package or service, and it changes
nothing about log building, schedule rules, the Django Admin fill configuration, Hour Refill (Roadmap 2.27), Web
Requests, Remote DJ, the encoders or the protected updater.

**The playout engine is restarted by this release** (r0134 did not restart it). See the deployment declaration and
`r0135_installation.md`.

## What happened on 2026-11-11

1. Between 21:48 and 21:51 the operator deleted three Weather MP3 Tracks as part of the r0134 FLAC cutover. The 21:00
   log still held three rows that pointed at them. Deleting a Track keeps its historical log rows and clears their
   Track reference, which is the intended behaviour.
2. The final song of the hour was going to end about 208 seconds early, so the engine asked the legacy live filler to
   top up the hour from the configured PSA fallback, as it normally does.
3. The filler read the whole queue as recent history. It tried to read the Track of the three rows whose Track was
   gone, and failed every time (journal: `Live-fill worker crashed (non-fatal): 'NoneType' object has no attribute
   'id'`, from 21:54:55 on). No PSA was ever added, and the last song ended into silence at 21:56:39.
4. While the queue was empty, every 10-second scheduler check started one more 30-second "try the next hour again"
   timer, and none of them ever stopped. When the 22:00 log was installed early at 21:59:34, those leftover timers
   kept reloading the 21:00 log, rolled forward again and started further 22:00 items while the first one was still on
   air. The Calendar of Events started over the 1990 Intro, and a promo followed.

## What changes for the operator

### Legacy live fill keeps working when history references deleted Tracks

- The filler now skips history rows whose Track no longer exists when it works out what aired recently. It still uses
  every remaining valid row for its separation rules.
- It still uses Django Admin's **Log fill config** (`LogFillConfig`) exactly as configured, including a fixed PSA
  fallback Category. Its selection rules, separation, duration-fit margin and how its additions are installed are
  unchanged. Rows with a deleted Track stay in the log as before; nothing deletes, renumbers or rewrites them.
- Deleting a Track that already sits in a live or upcoming log no longer stops the filler. The engine still skips
  that row at play time, exactly as before.

### Recovery when a log runs out

- **One retry owner.** When a log runs out, the engine keeps exactly one pending "try the next hour" retry. Every
  later attempt reuses it, so retries no longer pile up.
- **No stale starts.** A retry only acts when both decks are idle. It never moves the active queue back to an older
  hour once a newer one is installed, and it never starts anything over programming that is already on air.
- **Logs with nothing playable wait.** An approved next-hour log in which every remaining item is unplayable (deleted
  Tracks, missing files, cleared paths) is reported once as an "Approved log has no playable item" warning, and the
  engine waits on the single retry. It no longer loops reloading and skipping that log. This covers ordinary next
  hours and partial-hour (mid-hour takeover) logs.
- **Manual mode is respected.** An automated retry that fires while the station is in Manual (including a microphone
  hold) starts nothing. Playback resumes through the normal paths when the station returns to Auto, and only once.
- Engine shutdown cancels a pending retry.

### Aired items are not replayed; pending inserted items are not lost

- An item that has already started airing is never started again as an ordinary queue item. This holds even when the
  queue position alone would point at it, such as after an engine restart or a queue reload. Before this release a
  restart could replay aired items that followed an unplayable row.
- Items the engine inserts out of their stored order are kept until they air, across an engine restart (with or
  without resuming the interrupted item) and across the engine's periodic queue reload. These are urgent inserts
  (WxAlert, which carries NWS and AMBER-family alerts, and any other `insert_urgent` category), native Active Messages
  and dedication intros. A newer urgent item can air before an older one (it is placed first), and a restart after the
  newer one aired used to drop the older one.
- Ordinary log items that the engine had already passed because they were unplayable are not offered again after a
  restart.
- The exact resume of the item that was interrupted by a restart, dedication follow-up protection, urgent priority,
  the native Active Message placement behind Weather/AMBER items, and DST fall-back replay are unchanged.

### Quieter playability check

The engine's internal "is anything playable next?" check now only looks at the poison-guard list. It no longer writes
a monitoring event or touches the database. The real selection still refuses a poison-guarded item and reports it
once, as before.

### Unchanged

- **Hour Refill (Roadmap 2.27)** is independent of this fix and unchanged. On KOGR it stays in Stage 3
  observation-only mode with the host unarmed. The KOGR incident was not caused by Hour Refill, which correctly
  installed nothing.
- Log building and schedule resolution. The filler function is shared with log building, and its only change is that
  history rows with a deleted Track are skipped; with no such rows its results are identical.
- Crossfades, voice tracking, Start Next, dedications, Web Requests, Remote DJ and the poison guard's own rules.

## What has and has not been demonstrated

Demonstrated:
- Both 2026-11-11 failures were reproduced on r0134 in deterministic tests. These run the engine's real live-fill,
  retry, recovery, rollover and queue-selection code, with stand-in decks and a simulated clock. The fixed code passes
  the same tests: no crash, a PSA fill of the short hour, one rollover, no overlapping starts, no stale retry timers.
- Each review correction was first shown failing on the commit it corrects, then passing.
- The surrounding playout, live-fill, DST, Start Next, restart/resume, dedication and Hour Refill test modules pass,
  apart from errors that already exist on r0134.

Not demonstrated:
- **No end-to-end acceptance with real GStreamer playout has taken place.** On the stations, acceptance is passive
  observation after installation. Do not recreate the incident on air.
- **The full Library test suite is not green.** It has 73 errors that already exist on the baseline: voice-tracking,
  branding and track-deletion tests that fail on this environment's media validation and read-only sandbox, unrelated
  to playout. The same 73 occur with and without r0135; this release adds none.
- **The native Active Message integration suites cannot run in the test environment.** Their media fixtures are
  rejected by its media validation, identically on the previous engineering commit. Native Active Message ordering
  across a restart is covered by one engine-side test with the message-domain admission step stubbed.
- r0135 does not promise gap-free audio in every circumstance (see Known limitations).

## Known limitations (accepted, not fixed here)

- **Short silence before the next hour is still possible.** The legacy filler stops adding items when the remaining
  time is within its 30-second duration-fit margin (`DURATION_FIT_MARGIN`). With randomly chosen PSAs, a filled hour can
  still end up to 30 seconds early; a 3-second gap was observed in testing. Changing that margin is a separate design
  decision.
- **Unavailable items can be processed repeatedly.** While an approved log stays entirely unplayable, the engine's
  10-second idle recovery still steps over it on each check. That work is bounded and its warnings are de-duplicated,
  and the automatic-skip cause rows for Hour Refill are de-duplicated as well.
- **Inserted items can come back late.** An urgent, native Active Message or dedication-intro insertion that was
  skipped because its media was unavailable is reconsidered after an engine restart. If its media has returned by
  then, it can air late. Before r0135, every unaired row was reconsidered after a restart.
- Native Active Message integration testing remains subject to its validated-media environment (see above).

## Deployment declaration

There are no migrations, migration companion, packages, Python requirements, collectstatic, nginx, systemd units or
protected-runtime changes. `protected_runtime` is `null`, so no protected descriptor, policy generation, offline
release signature or attestation is created.

Restarts, in canonical order: `isadoraair-gunicorn`, then `isadoraair-engine`. The release changes two production
modules, the engine (`library/services/engine.py`) and the log builder (`library/services/log_builder.py`). Both are
loaded by the engine and by the Gunicorn web process (log builder through the web views, engine constants through web
modules). No other long-running service imports either one: Monitoring, RBDS, the encoders, Active Messages, spoken
rendering, production rendering and validation are not restarted. Timer-started commands start fresh processes and pick
up the new code on their next run.

**The engine restart interrupts program audio briefly and ends any active Remote DJ session.** On restart the engine
resumes the interrupted item from its saved position when that state is valid, as it does today. KOGR and WRJE each
need separate installation authorization; see `r0135_installation.md`.
