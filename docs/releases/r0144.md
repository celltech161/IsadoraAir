## A — Engine restart safeguard

The three places a Django operator can ask for an **audio engine restart** now check the engine's own status first:

- **Update Center**: an install whose trusted plan restarts `isadoraair-engine` (a Gunicorn-only plan reads no engine
  status and is never gated);
- **Monitoring**: the Restart action for the engine's own unit only (other services' Restart is unchanged);
- **Django Admin, Audio Pipeline**: a save that changes `sample_rate` or `program_gain_db` (the fields that restart the
  engine); other saves are unchanged.

The check reads `/run/isadoraair/engine_state.json` (read-only) and is **safe**, **warning** (Manual mode, or a
quarantined Remote DJ slot, whose documented recovery is a restart), **blocked** (studio microphone live, Remote DJ
microphone live, a Remote DJ connected even with its microphone Off, reconnecting, establishing, or its slot occupied or
cleaning) or **unknown**. Unknown covers missing, unreadable, stale (> 10 s), future-dated, malformed, unsupported or
contradictory status, including a missing or mismatched engine identity (`engine_session_id` / `state_revision`), a
transport other than `PLAYING`/`STOPPED`, or missing Remote DJ lifecycle fields. **Unknown is never treated as safe.**

Blocked and unknown are refused unless a **superuser** overrides that one request with a written reason (at least 8
characters). Nothing is stored between requests. Every refusal, override and overridden request's outcome is recorded
as a Monitoring event (category `restart_safety`); an outcome describes the *request* and never claims the engine
restarted. The engine, its Auto/Manual semantics, restart recovery, microphone ownership, Remote DJ/WebRTC teardown,
systemd automatic recovery, the protected updater and the broker are unchanged. Details:
`docs/ENGINE_RESTART_SAFEGUARD.md`.

The safeguard applies to restarts requested **after** r0144 is running: the r0144 installation itself is started from
the previously installed Update Center and does not restart the engine for a direct r0143 → r0144 update.

## B — Library unique Artist count

`/library/` shows the number of distinct Artists beside the Track count (for example `5 tracks · 3 artists`). Both come
from the same `/api/tracks/` response (`artist_total`), computed over every Track matching the current search, Category
and status filters (not only the visible page) by one `COUNT(DISTINCT artist_id)`-style query. Only the newest list
request may update the page: an earlier request is aborted and a late answer for an earlier filter is discarded, so the
totals and rows always belong to the filter on screen.

## C — Bulk Edit Related Artists

The `/library/` Bulk Edit dialog has a **Related Artists** row immediately below Artist: **Leave unchanged**, **Set
to**, **Append** or **Clear**, with comma-separated names as in the single-Track editor. It uses the shared
`library.services.related_artists` rules: names are trimmed and deduplicated case-insensitively (first spelling wins,
order kept), Append keeps every existing entry, and each Track's primary Artist is left out. When Artist is set in the
same edit, names are normalized against the **resulting** primary Artist. The 500-character limit is enforced without
truncation: a list that is itself too long is refused, and a Track whose appended list would not fit is refused and left
unchanged (reported in the preview and the result). A list that differs only in formatting is unchanged. The preview
shows each Track's before/after value; a Track whose Related Artists or primary Artist (or that Artist's name) changed
since the preview is reported stale and left alone. Selection limits, preview/apply tokens, authorization, audit and
per-Track locking are unchanged. Database metadata only: no audio file, tag, cue marker or file location changes.

Bulk-edit previews made before the update are reported stale after it (the preview fingerprint now covers Related
Artists); preview again.

## Limitations (accepted; not remediated in r0144)

1. **The engine restart safeguard checks admission, not eventual restart execution.** A microphone or Remote DJ state
   may change after the request is admitted, particularly during a multi-step Update Center installation, where the
   engine restart can come minutes after admission. A browser that holds a Remote DJ token but has not reached the
   engine yet is not visible in engine status.
2. **A concurrent rename of a cached target Artist during Bulk Edit Related Artists may leave the renamed primary Artist
   represented in Related Artists.** This narrow P3 concurrency case does not compromise set-based scheduling identity
   calculations.

The original durable Manual-mode restoration scope of roadmap 1.20 remains **deferred**. Roadmap 2.25 (evergreen Voice
Track transitions) is **not** part of r0144.

## Unchanged behavior

r0144 does not alter the audio engine, playback or scheduling, the levels or status endpoints, Remote DJ admission or
WebRTC, Hour Refill, Web Requests, Weather/AMBER alerts, Active Messages, the protected updater or broker, or any
station setting or stored content.

## Operational impact

There is no migration: `migrations_required` is empty and `migration_compatibility` is `null`. There are no new
packages, Python requirements, static assets, collectstatic, nginx changes, systemd units, manual bootstrap or
protected-runtime changes: `protected_runtime` is `null`. Restart exactly:

1. `isadoraair-gunicorn`

Under a direct r0143 → r0144 update **the audio engine and encoders remain running** and program audio is not
interrupted. After installation, reload open `/library/`, Monitoring and Update Center pages. A station on an earlier
release still receives every intervening migration and restart in its cumulative plan.

Publication does not authorize installation: each station requires separate preflight, installation authorization and
operational acceptance; see `r0144_installation.md`.
