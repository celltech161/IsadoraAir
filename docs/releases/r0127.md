# r0127: Frontend Duplicate Resolution

r0127 delivers roadmap 3.12's operator workflow for resolving exact duplicate Track pairs from
**Library → Reconciliation**. An account with **Manage tracks** can choose which Track to keep, keep
both intentionally, preview every effect and explicitly confirm an eligible deletion. **No action**
remains the default. Nothing is selected or deleted automatically.

This release extends the existing reconciliation report. It does not add a scanner, schedule,
background service, generalized merge facility or broader duplicate classifier.

## Supported findings and choices

The workflow is offered only when a completed reconciliation report identifies exactly two Tracks
with matching bytes and records the complete file witness used during hashing. Groups of three or
more Tracks, likely duplicates, shared-source findings and metadata-only similarities remain
read-only.

For each eligible pair an operator may:

* keep Track A and discard Track B;
* keep Track B and discard Track A;
* keep both and record that they are not duplicates; or
* take no action.

Both Track Detail links remain available for listening and comparison. Categories present only on
the discarded Track are suggested as editable additional categories on the survivor. The survivor's
primary category, readiness, audio, waveform and cue markers are not replaced or merged.

Legacy pending deletion decisions are displayed for context but are not executable by this browser
workflow. A fresh operator choice and preview are required.

## Deletion safeguards

Preview is read-only. Before issuing a short-lived, operator-bound, single-use token for one pair,
the server verifies the latest completed scan, both Tracks and files, the complete six-field
scan-time file witnesses, categories and references. It blocks deletion when the discarded Track is
protected, missing, changed, scheduled in a current or upcoming log, present in the engine's active
log, on a deck or in the engine queue, recently claimed or plausibly still playing.

The engine state must be present, fresh, readable and structurally complete. Its timestamp must be a
finite number no older than 30 seconds and no more than five seconds in the future; both playback
decks, the queue and active-log field must be reported. Keep Both deletes nothing and therefore does
not require engine availability.

Tracks referenced by rotations or playlists remain protected. A Track with VoiceTracks requires a
separate **Delete Anyway** acknowledgment explaining that those VoiceTracks are deleted by the
existing database cascade and are not moved to the survivor. Upcoming-log blockers link to the
affected log hours; this workflow never edits or regenerates a log.

At apply, the server observes engine state again, locks and revalidates the pair, and compares its
current fingerprint with the preview. Category additions and deletion commit in one transaction or
roll back together. Each request can apply only one pair.

## Browser sequencing and partial outcomes

The browser confirms the selected batch once, then submits independently authorized pairs one at a
time. A blocked, stale, busy or definitive 4xx refusal is reported without rolling back earlier
pairs, and processing may continue to the next eligible pair.

A lost response or any HTTP 5xx response is uncertain: the deletion may have committed before a
worker or proxy failed. The browser marks that pair **Unknown**, marks later pairs **Not attempted**,
stops without retrying and reloads current findings. Tokens cannot be replayed or substituted across
operators, pairs or category choices.

Changing the page, filters or debounced search with unresolved selections requires an explicit
choice to stay or discard them. A newer scan clears stale selections with an explanation.

## Cleanup and auditing

Database deletion commits before source and waveform cleanup. Source cleanup reports whether the
file was removed, already absent, retained for a safety reason, pending or failed. A retained or
failed source does not mean the deleted Track row was restored. Waveform cleanup failures are logged
and may leave a safe orphan cache for later reconciliation.

Every pair outcome records a Library audit event. Operators should run reconciliation again after
finishing a cleanup session rather than treating the old report as current.

One deletion request has a cumulative controllable lock-wait budget of nine seconds: token claim
one second, expired-claim cleanup one second, pair transaction three seconds, source cleanup two
seconds and waveform cleanup two seconds. This bounds lock waiting, not total HTTP execution time.

## Transition from r0126

r0126 and earlier reports do not contain the complete scan-time witness required to authorize a
deletion. They remain readable, and Keep Both remains available, but r0127 will block deletion from
them. After installation, an operator must deliberately run a new reconciliation scan before using
the deletion workflow.

## Deployment declaration

* **Migration:** none; no migration-authorization companion exists or is required.
* **Python requirements and APT packages:** unchanged; no dependency installation.
* **Systemd and protected runtime:** no unit, timer, policy, descriptor, attestation or protected
  generation change. `protected_runtime` is `null`, so no offline release signature is created.
* **Static and nginx:** unchanged; no `collectstatic` action.
* **Restart:** `isadoraair-gunicorn` only, so Gunicorn workers load the new endpoints and page.
* **Not restarted:** engine, encoders, Monitoring, RBDS, Active Messages, reconciliation processes,
  spoken rendering and every other station service.

Publication does not authorize installation at KOGR or WRJE, running a production reconciliation
scan or deleting a production Track. See [r0127_installation.md](r0127_installation.md).

## Not in this release

* no automatic duplicate resolution or unattended deletion;
* no likely-duplicate or three-or-more-Track resolution;
* no metadata, cue-marker, waveform or primary-category merge;
* no log, rotation, scheduler, engine, encoder or playout change;
* no Hour Refill or native Active Messages activation.
