# r0143: Console VU meter staleness window

r0143 changes one console template, `library/templates/library/dashboard.html`, and adds a regression test. Restart
**Gunicorn only**.

## Problem

On November 16, 2026 the console **Program Level** VU meter stayed blank on an operator PC while program audio was
normal. The station side was healthy: the engine was rewriting `/run/isadoraair/levels.json` every few hundredths of
a second and `GET /api/engine/levels/` answered HTTP 200 with fresh samples to that browser.

## Cause

The console judges a level sample stale by comparing the **viewer's clock** with the engine's sample timestamp, and
renders a stale sample as silence. The window was **0.75 s**. The operator PC's clock ran about **0.84 s ahead** of
the NTP-synchronized station (measured round trip about 0.02 s), and Windows time synchronization did not remove the
offset, so every sample was treated as stale.

## Change

Both meters that use this check — **Program Level** (`pollLevels`) and the **Remote Mic PTT** button meter
(`renderRemoteDjVu`) — now share one constant, `VU_STALE_SECONDS = 1.0`. A viewing device whose clock runs up to
about a second ahead of the station now shows the meter. A sample older than 1.0 s by the viewer's clock still
renders as silence, so a stopped engine or lost connection still blanks the meter.

## Limitation

The check still depends on the viewing device's clock. A device more than about one second ahead of the station
(less any network delay) will still show a blank meter; keep viewing devices time-synchronized. Measuring the sample
age on the station instead is a possible later change and is not part of r0143.

## Testing

- **Template regression** (`library/tests/test_vu_staleness_window.py`): one shared 1.0 s constant, used by both
  meters, with no other hard-coded level-staleness window. With the console, connection-stale, dashboard and Remote
  DJ meter tests: **52 of 52**.
- **Browser check** (rendered console, scripted levels endpoint, host Chromium): with samples 0.50, 0.87, 0.95 and
  1.30 s old, the corrected page shows signal, signal, signal and silence. The r0142 page shows signal at 0.50 s and
  **silence at 0.87 s**, reproducing the field symptom.
- **Review:** the operator waived independent Codex review for this template-only change.

## Unchanged behavior

r0143 does not alter the levels endpoint, the engine's level measurement or file, the meter scale, colors or ballistics,
Remote DJ LIVE/OFF authority, Past Overrides, Console NEXT or Swap, the playback engine, Web Requests, Hour Refill,
Weather/AMBER alerts, Active Messages, or any station setting or stored content.

## Operational impact

There is no migration: `migrations_required` is empty and `migration_compatibility` is `null`. There are no new
packages, Python requirements, static assets, collectstatic, nginx changes, systemd units, manual bootstrap or
protected-runtime changes: `protected_runtime` is `null`. Restart exactly:

1. `isadoraair-gunicorn`

Only Gunicorn renders the console template; no Python module changed. Under a direct r0142 → r0143 update **the audio
engine and encoders remain running** and program audio is not interrupted. After installation, reload open console
pages to pick up the new template. A station on an earlier release still receives every intervening migration and
restart in its cumulative plan.

Publication does not authorize installation: each station requires separate preflight, installation authorization and
operational acceptance; see `r0143_installation.md`.
